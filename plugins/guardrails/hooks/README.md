# Guardrails hooks

[`hooks.json`](hooks.json) holds every hook of the kit as an inline `python3 -c` command. Hooks are a guard, not a guardrail: they fail open, load only in local Devin and Claude Code, and cannot replace user confirmation or the always-on safety boundaries. Reader: a kit contributor who changes a hook or its tests. Paths are from the kit repository root, and the test files are in `platforms/ci/validations/`.

## Hooks

The timeout ceiling is the most `platforms/ci/validations/check_kit.py` accepts for the event; `hooks.json` may set less.

| Hook | Event, matcher, timeout ceiling | Behaviour | Tests |
|---|---|---|---|
| Guard | `PreToolUse`, `^(exec\|Bash)$`, 10 s | Denies a destructive command. Its one network call, the KIT-020 merged-branch check behind `git branch -D <name>`, fails closed: any `gh` or `git` error or timeout denies. | `hook_guard_cases.json`, run by `check_kit.py`; `test_hooks_guard_merged_branch.py` covers the merged-branch check with a stub `gh` |
| Git context | `PreToolUse`, `^(exec\|Bash)$`, 10 s | Only adds context and never denies (KIT-071): after a `git commit` or `gh pr create` it adds the `git` essentials for the next step. Claude Code shows `additionalContext` next to the tool result, so it reaches the model after the command ran. `check_kit.py` tells it by its `ai-kit git, after this ` text. | `hook_git_context_cases.json` (commit, PR and silent commands), run by `check_kit.py`; `test_hooks_context.py` |
| Format and lint | `PostToolUse`, `^(edit\|write\|Edit\|Write)$`, 30 s | A missing tool exits 0 with a notice; findings exit 2 with the tool output on stderr. | `hook_post_edit_cases.json` covers every branch; `check_kit.py` runs it with stub tools |
| Synced-folder warning | `SessionStart`, `^(startup\|compact)$`, 10 s | Always exits 0. Its compact branch adds the Git state after compaction. | `hook_session_start_cases.json`, run by `check_kit.py` on a throwaway `HOME` with a stub `xattr`; `test_hooks_guard_compact.py` covers the compact branch |
| Session-start checklist | `SessionStart`, `^(startup\|clear)$`, 10 s | Only adds context and never denies (KIT-071): the checklist, plus the attribution line below. `check_kit.py` tells it by its `ai-kit session start:` text. | `check_kit.py` runs it on the four settings cases below; `test_hooks_context.py` |
| Attribution | `SubagentStart`, no matcher, 10 s | Only adds context and never denies (KIT-071): the attribution line below. It is the checklist's command with another event argument, because session-start context does not reach a subagent. `check_kit.py` tells it by its `ai-kit attribution:` text. | `check_kit.py` runs it on the four settings cases below; `test_hooks_context.py` |
| Rule-load log | `InstructionsLoaded`, no matcher, 5 s | Only records (KIT-070): for each `CLAUDE.md` or `.claude/rules/*.md` load it appends one JSON line (time, session, cwd, file path, memory type, load reason, globs, trigger and parent file; never content or the transcript path) to `${CLAUDE_PLUGIN_DATA}/instructions-loaded.jsonl`, rotated past 5 MiB under one lock with the append (`instructions-loaded.jsonl.lock`, `flock` where the platform has it, so concurrent sessions lose no line, #274), prints nothing and exits 0. `platforms/tools/skill_usage.py --rules` counts it. `check_kit.py` tells it by its `ai-kit rule-load log` text. | `check_kit.py` runs it on one path-rule load with a throwaway data folder; `test_hooks_instructions_loaded.py` covers malformed input, a missing or unwritable data folder, the rotation, latency and broken copies that `check_kit.py` must fail |

- Attribution line: both start hooks add the commit trailer and PR footer, which `includeGitInstructions: false` removes from Claude Code's prompt, only while the user, project and local settings files leave that key at `false`, with the user's own `attribution.commit` and `attribution.pr` text where set and nothing for an empty one, `attribution: false` or `includeCoAuthoredBy: false`.
- Settings cases: `check_kit.py` runs both start hooks on four settings cases (off, default, hidden attribution, a custom trailer) with an empty `HOME`; `test_hooks_context.py` covers the settings layers, malformed input, latency and broken copies that `check_kit.py` must fail.
