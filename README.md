# agent-rules-kit

A plugin-first source of always-on rules, triggered rules, skills, references and templates for Devin Cloud, Devin CLI/Desktop, Codex and Claude Code. Plugin content lives under [`plugins/`](plugins/) — fourteen plugins (thirteen in the default `all` bundle plus the opt-in `extras`) with shared manifests; tooling and documentation stay at repository root.

**Repository layout:** [`INDEX.md`](INDEX.md) · **Maintenance:** [`docs/maintenance.md`](docs/maintenance.md)

## Bootstrap

```bash
git clone https://github.com/ChristianPrzybulinski/agent-rules-kit.git ~/.ai-kit && ~/.ai-kit/platforms/tools/bootstrap.sh
```

## How each agent loads the kit

| Agent | Always-on | Skills/rules | Refresh |
|---|---|---|---|
| Devin Cloud | required plugin `plugins/core/AGENTS.md` | `plugins/*/skills/` and `plugins/*/rules/` | fetches `main` per session |
| Devin CLI/Desktop | root meta-plugin requires `core` | required plugin plus optional satellites | app startup; doctor updates stale SHA |
| Codex | `~/.codex/AGENTS.md` → `~/.ai-kit/plugins/core/AGENTS.md` | marketplace plugins plus temporary fallback symlinks | launchd every six hours |
| Claude Code | `~/.claude/CLAUDE.md` → `~/.ai-kit/plugins/core/AGENTS.md` | marketplace plugins; path rules from the repo's `.claude/rules/<plugin>-<rule>.md` and project skills vendored in `.claude/skills/` (both generated by `sync-project.sh`, skills with `--vendor-skills`); user-level `~/.claude/rules/<plugin>-*.md` symlinks only with `AI_KIT_USER_RULES=1` | launchd every six hours |

User-level rule symlinks are opt-in with `AI_KIT_USER_RULES=1` (a rule present in both `~/.claude/rules/` and the repo's `.claude/rules/` loads twice); repos carrying `.claude/rules` need nothing, and `doctor.sh` removes the old symlinks by default.

## Platform behavior

| Agent | Hooks | Path rules | Subagents | User-only skills |
|---|---|---|---|---|
| Devin Cloud | no | `globs` | managed Devins | `triggers: [user]` |
| Devin CLI/Desktop | PreToolUse guard, PostToolUse format/lint and SessionStart synced-folder warning, best effort | `globs` | shared profiles | `triggers: [user]` |
| Codex | no | description routing | no | `agents/openai.yaml` policy |
| Claude Code | PreToolUse guard, PostToolUse format/lint and SessionStart synced-folder warning, best effort | `paths` | shared profiles | `disable-model-invocation: true` |

## Devin plugin

The existing repository source remains valid: the content-free root meta-plugin requires the `all` bundle, so installing the repo restores the full kit — and every content plugin is listed as optional for minimal setups:

```bash
devin plugins install ChristianPrzybulinski/agent-rules-kit                # everything (via all)
devin plugins install ChristianPrzybulinski/agent-rules-kit#plugins/dev-java  # one satellite + its chain
devin plugins install ChristianPrzybulinski/agent-rules-kit#plugins/extras   # opt-in extras (not in all)
```

Existing Customize entries need no source change; Reindex to pick up the new dependency. The legacy `ai-kit` plugin should be removed (`devin plugins remove ai-kit`) — its path no longer exists. Run `devin plugins update` to force a local refresh.

## Codex

Bootstrap registers the marketplace and every plugin:

```bash
codex plugin marketplace add ChristianPrzybulinski/agent-rules-kit --ref main
codex plugin add core@ai-kit   # repeat per plugin, or let bootstrap/doctor iterate them
```

The root marketplace catalog lists all fourteen plugins; `~/.codex/AGENTS.md` links to `~/.ai-kit/plugins/core/AGENTS.md`. While [openai/codex#22078](https://github.com/openai/codex/issues/22078) remains open, doctor maintains fallback skill symlinks to `~/.ai-kit/plugins/*/skills/` and removes them once plugin skills are exposed. On Codex, bootstrap installs every catalog entry including `extras`; remove it afterwards with the Codex CLI's plugin removal command if unwanted (not verified here: no Codex CLI on the maintainer's machine).

`bootstrap.sh`, `refresh.sh` and `doctor.sh` find the Codex CLI through `platforms/tools/codex-bin.sh`: `$CODEX_BIN` when set, then `codex` on `PATH`, then the CLI bundled in ChatGPT.app or Codex.app, then `~/.cache/codex-runtimes`. A `CODEX_BIN` that is not executable is reported and no other CLI is used. Run `platforms/tools/codex-bin.sh` to see which CLI the kit uses.

## Claude Code

```bash
claude plugin marketplace add ChristianPrzybulinski/agent-rules-kit
claude plugin install all@ai-kit    # or a single satellite; dependencies resolve automatically
claude plugin install extras@ai-kit  # opt-in: frontend-design, krita, dbeaver, find-skills, skill-creator
~/.ai-kit/platforms/tools/bootstrap.sh
```

Bootstrap links the shared AGENTS file to `~/.claude/CLAUDE.md`, links every plugin path rule under `~/.claude/rules/<plugin>-<rule>.md`, and narrows Devin imports so the same Claude file is not loaded twice. The marketplace `renames` entry migrates installed `ai-kit` to `core`.

A repository that vendors its skills (`sync-project.sh --vendor-skills`) enables only `core@ai-kit` in `.claude/settings.json` (kept for the guard hook, which lives in the plugin only). Enabling the other profile plugins too makes each skill load twice (`/plugin:name` and `/name`); prefer the vendored copy, because it is the only form that reaches Claude Code cloud sessions, the GitHub Action and Devin Cloud.

## Refresh and diagnosis

On macOS, launchd runs `platforms/tools/refresh.sh` at login and every six hours. `platforms/tools/doctor.sh` repairs clone, plugin and symlink state, warns when a Claude plugin cache differs from the kit (`refresh.sh` reinstalls it, KIT-013), and sets Claude Code's `autoCompactWindow` to `200k` when `~/.claude/settings.json` has none (KIT-010). Nothing refreshes at agent session start.

## Maintainers

Each directory under `plugins/` is a plugin with three manifests; the repository root is a content-free meta-plugin. Before a PR, run `platforms/tools/check.sh` and `platforms/tools/smoke.sh`. Content changes follow `docs/maintenance.md`. Never add non-rule files to any `plugins/*/rules/`; `plugins/*/agents/` contains only schema-validated shared profiles, and only `plugins/core/` carries `AGENTS.md` and `hooks/`.
