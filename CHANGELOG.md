### Added
- KIT-113 (#389): an owner question that stays unanswered no longer stops an SDD step. After `sdd.owner_wait_minutes` (new profile key, integer, default 10) the step notifies the owner once through the runtime's push tool if it has one, continues on the marked recommendation and writes it as a `[DECISION] pending owner: <option> (asked YYYY-MM-DD HH:MM UTC)` line in the artifact it shapes, finishes the chain in the same branch and stops before the merge; the spec PR lists pending decisions first (`sdd-clarify` § 2, `sdd-plan` § 5; the key is in `sdd-parameters.md`). `check_spec.py` rule `pending-decision` fails a line that starts with that marker in any spec Markdown file, naming `file:line`, so the merge is blocked by the spec check (where it runs on the PR as a required check, with the finding not baselined), not by prose; a spec that quotes the marker inside running text passes. The owner's answer rewrites the line to `[DECISION] <option>, chosen by the owner on YYYY-MM-DD`, which passes, then it is folded as usual. Migration: none to adopt; a project whose spec holds a pending line must resolve it (the owner's answer, then the line rewritten or folded) before the merge, and a project that wants a different wait sets `sdd.owner_wait_minutes` in `.ai-kit.yaml`.
- KIT-107: `review_checks.py red --exclude GLOB` (repeatable) leaves generated output out of the code roots, so a PR whose only code change is generated reports `red: EXEMPT` and the project's generator check stays its proof. The run prints each excluded path, and a hand edit beside the generated files still counts (`red: NONE`). `--plan` and `--sides-from` share the selection. Without the flag nothing changes. Migration: none; a project whose `red` row fails on generated output adds `--exclude '<glob>'` to it.
- KIT-109: `platforms/tools/check_changelog.py`, run by `check.sh` and so by the `static` job, fails a pull request whose diff adds a `CHANGELOG.md` line under a released `## [X.Y.Z]` section, naming the line and the section (`CHANGELOG.md:12: added under [17.1.0], a released version; move it under [Unreleased]`). A rebase or merge across a release can land a branch's line there with no conflict. The base is the merge base with `origin/main`, else `HEAD^1`; a release diff that adds its own heading passes. The `static` job checks out with `fetch-depth: 2` so `HEAD^1` exists. Migration: none.

- **Layout v4**: `rules/`, `knowledge/`, `prompts/` → `agents/`; skills by type in `agents/skills/<type>/`; `processes/sdd/` → `agents/skills/process/`; flat templates in `agents/templates/` (`spec-*`, `doc-*`, `project-*`, `kit-*`); `schemas/`, `scripts/` → `platforms/ci/` and `platforms/tools/`/`platforms/install/`; `kits/` → `platforms/kits/`. Master index: `INDEX.md`.
- **BREAKING**: public paths changed — `scripts/check.sh` → `platforms/tools/check.sh`, `scripts/install/all.sh` → `platforms/install/all.sh`, `templates/docs/spec/*` → `agents/templates/spec-*`. Projects must update references (e.g.: `spec-lint.yml`).
- `check.sh` now delegates to `platforms/ci/validations/check_kit.py` (layout, frontmatters, indexes, links, lock, duplication); `--spec` remains in `check_spec.py`.
- `devin.sh`/`codex.sh` install skills from `agents/skills/`; `cursor.sh` ignores `INDEX.md`; `all.sh` writes `~/.config/agent-rules-kit/{VERSION,LAYOUT_VERSION}` and gains `--clean`.
- Releases are now automatic: tag `v*` → workflow validates `VERSION` and publishes a release with the changelog section.

### Added
- `VERSION`, `LAYOUT_VERSION`; root `INDEX.md` + INDEX/README in every folder.
- `platforms/tools/`: `bootstrap.sh` (1 command) and `refresh.sh [--quiet]` (pull + reinstall by version/layout).
- `.github/`: `ci`, `gitleaks`, `release` workflows; `dependabot.yml`; PR template; CODEOWNERS.
- `platforms/ci/schemas/`: `rule`, `knowledge`, `skill`, `skills-lock` (besides the 5 spec schemas).
- `agents/rules/core/sessions.md` (session hygiene) and `agents/templates/kit-*.md` (templates for the kit itself).
- `docs/`: `design.md` (principles), `projects.md` (what lives in the project), `maintenance.md` (versioning, vendor, CI).
- `knowledge.schema.json` frontmatter on the 9 `agents/knowledge/` notes.
