# Glossary

Plain definitions of the terms a newcomer meets in this repository. Each entry names the file and line that say it; line numbers are exact at the commit that adds this file, so search the quoted text if one has moved. Where a document disagrees with the code, the entry follows the code. Terms the repository uses without defining are listed at the end, not guessed.

Read next: [README](../README.md) for install and platform behavior, [CONTRIBUTING](../CONTRIBUTING.md) for where content goes and the checks, [design.md](design.md) for the principles.

## A

- **AGENTS.md (consumer repository)**: A consumer repository's own rule file, filled in from a `project-agents-*` template; it overrides the kit's always-on rules. The kit's own root has none, because a root `AGENTS.md` would load in every Devin session on top of the plugin's. Source: `plugins/guardrails/AGENTS.md:3`, `docs/projects.md:9`, `CONTRIBUTING.md:22`.
- **Agent (supported agent)**: One of the four coding agents the kit targets: Devin Cloud, Devin CLI/Desktop, Codex and Claude Code. Each loads the always-on file, the rules and the refresh differently; see *subagent profile* for the other sense of "agent". Source: `README.md:3`, `README.md:25`.
- **`AI_KIT_USER_RULES`**: An environment variable that decides whether the kit keeps user-level symlinks of its path rules in `~/.claude/rules/` for Claude Code. The default is `0` and `doctor.sh` removes the old symlinks, because consumer repositories carry their own `.claude/rules` and a rule present in both places loads twice; `1` keeps them. Source: `README.md:34`, `README.md:77`, `platforms/tools/doctor.sh:192`, `platforms/tools/README.md:7`.
- **Always-on rules**: `plugins/guardrails/AGENTS.md`, the one short file the kit gives every agent as its always-loaded instructions: Devin Cloud reads it as the required plugin's file, Devin CLI/Desktop through the root meta-plugin, and Codex and Claude Code through `~/.codex/AGENTS.md` and `~/.claude/CLAUDE.md`, which link to it. A line stays only if the behavior must hold before any skill could trigger, and `check_kit.py` caps the file at 60 lines. Source: `plugins/guardrails/AGENTS.md:3`, `docs/design.md:16`, `platforms/ci/validations/check_kit.py:24`, `README.md:29`, `README.md:30`, `README.md:31`, `README.md:32`.

## B

- **`bootstrap.sh`**: First-time setup of a machine: it clones the kit to `~/.ai-kit` (or `$AI_KIT_DIR`), connects the agent plugins, installs the launchd refresh agent, then runs `doctor.sh`. Source: `platforms/tools/README.md:5`, `platforms/tools/bootstrap.sh:5`, `README.md:22`.

## C

- **Changelog rule**: Every visible change adds a line to `CHANGELOG.md` under `## [Unreleased]`, and a change with a KIT record cites `KIT-NNN` there. The release script refuses an empty `[Unreleased]` section. Source: `.github/PULL_REQUEST_TEMPLATE.md:6`, `docs/features/README.md:18`, `CONTRIBUTING.md:35`.
- **Characterization test**: A test that pins what legacy or ported code does today, so a refactor has to change an explicit expectation. The always-on rules route legacy code to it before any refactoring. Source: `plugins/guardrails/skills/testing/references/characterization.md:8`, `plugins/guardrails/AGENTS.md:57`.
- **`check_kit.py`**: The Python validator that enforces the kit's invariants: root layout, manifests and dependency graph, frontmatter, the description budget, `INDEX.md` placement, links, backticked paths, the vendor lock and duplication. The PR checklist runs it with `--links`, which also checks links into `~/.ai-kit/...`. Source: `platforms/ci/README.md:24`, `CONTRIBUTING.md:20`, `CONTRIBUTING.md:91`, `.github/PULL_REQUEST_TEMPLATE.md:4`.
- **`check.sh`**: The kit's main local gate: it validates the kit and the Claude manifests, runs `gen_index.py --check`, and runs `claude plugin validate` when Claude Code is installed. `--spec <dir>` validates a project's specs instead. Source: `platforms/tools/README.md:17`, `CONTRIBUTING.md:90`, `CONTRIBUTING.md:92`.
- **Claim check**: A mode of skill `review`: an adversarial check of one claim or proposed fix, looking for contrary evidence first and ending in a sourced verdict with a confidence. Source: `plugins/guardrails/skills/review/references/claim-check.md:2`.
- **Claim tags**: Labels on every claim in a governed document: `[FACT]` (with its source), `[DECISION]`, `[PROPOSAL]`, `[HYPOTHESIS]` and `[BLOCKER]`. An untagged assertion counts as `[HYPOTHESIS]`, and the always-on rules apply the same tag to an answer's unsourced claims. Source: `plugins/guardrails/rules/spec.md:15`, `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:34`, `plugins/guardrails/AGENTS.md:48`.
- **Codex compatibility fallback**: Temporary symlinks from `~/.codex/skills/` to `~/.ai-kit/plugins/*/skills/` that `doctor.sh` maintains while Codex may leave plugin skills out of the model input, a condition the docs tie to openai/codex#22078 being open. `doctor.sh` removes the symlinks once the plugins expose the skills. Source: `docs/design.md:25`, `docs/design.md:27`, `README.md:65`.
- **Consumer repository (project)**: A repository that uses the kit. Rules, skills, references and templates are authored in the kit; the consumer keeps its own artifacts plus generated, version-stamped copies written by `sync-project.sh` (path rules, `CLAUDE.md`, `.claude/settings.json`, spec validation and, optionally, skills). Source: `docs/projects.md:3`, `docs/design.md:19`.

## D

- **Description budget**: The hard limit on skill descriptions: each is 40 to 160 characters with a literal `Use when` and `Not for`, and all of them together may use at most 7,200 characters, because Codex budgets about 8,000 for its initial skill list. Source: `docs/design.md:20`, `platforms/ci/validations/check_kit.py:27`, `platforms/ci/validations/check_kit.py:25`, `platforms/ci/validations/check_kit.py:26`, `CONTRIBUTING.md:91`.
- **`doctor.sh`**: The diagnosis and repair script: it verifies plugins and symlinks, warns when a Claude plugin cache differs from the kit, merges the Devin import policy, cleans legacy state and checks the budgets. Run it to diagnose a setup or after a refresh. Source: `platforms/tools/README.md:7`, `README.md:83`.

## E

- **Eval**: A test case for a skill, in `plugins/<plugin>/evals/<case>/`: a `prompt.md` plus `graders/*.md`, with `case.yaml` and `fixture.sh` when the case needs a repository. Cases run on demand with `claude plugin eval`; the suite holds one trigger case for each of eight critical skills, and a `skill-fired` grader checks that the skill fired. Source: `CONTRIBUTING.md:99`, `CONTRIBUTING.md:100`, `CONTRIBUTING.md:102`, `plugins/guardrails/INDEX.md:67`.

## F

- **FEAT, REQ and the other spec ids**: Identifiers of the spec files a consumer repository keeps under `docs/spec/`: `FEAT-nnn` (feature), `REQ-F-nnn` and `REQ-NF-nnn` (functional and non-functional requirements), `DTEC-nnn`, `DGME-nnn` and `DPRO-nnn` (decisions), `DEBT-nnn` (debts) and `J-nn` (journeys). Numbers are sequential per namespace and never reused; a FEAT lists its REQs and each REQ lists the FEAT, and a one-sided link fails `check_spec.py`. Source: `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:30`, `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:48`, `plugins/guardrails/rules/spec.md:14`, `plugins/guardrails/rules/spec.md:16`.
- **`Files` cell**: The column of a task table (skill `sdd-tasks`) that lists the files a task touches, test paths and generated files included. The always-on rules make it the task's scope (the request itself when there is no issue): a change needed outside it stops the work until the exact path is named. Source: `plugins/guardrails/AGENTS.md:10`, `plugins/guardrails/skills/sdd-tasks/SKILL.md:33`, `plugins/guardrails/skills/sdd-tasks/SKILL.md:48`, `plugins/guardrails/skills/sdd-tasks/SKILL.md:52`.

## G

- **Generated `INDEX.md`**: A per-plugin listing of its skills, rules, agents, templates, evals and hooks, produced by `gen_index.py` from the plugin's files and never edited by hand. `gen_index.py --check` fails on a stale one, and no other `INDEX.md` may exist in the repository. Source: `plugins/guardrails/INDEX.md:1`, `README.md:17`, `CONTRIBUTING.md:92`, `CONTRIBUTING.md:24`.
- **Glob rule**: See *path rule*. Source: `plugins/guardrails/rules/godot.md:3`.
- **Governed documents**: Documents under `docs/spec/**/*.md`, which the `spec` path rule governs: each starts from its governed template and keeps every section (none is compressed, summarized or dropped), and every claim carries a tag. The always-on rules and the `living-docs` reference extend the same discipline to "governed text" (specs, CHANGELOG, commits, comments, `AGENTS.md`, skills, protocol contracts), even inside a technical answer. Source: `plugins/guardrails/rules/spec.md:10`, `plugins/guardrails/rules/spec.md:12`, `plugins/guardrails/rules/spec.md:13`, `plugins/guardrails/AGENTS.md:29`, `plugins/guardrails/skills/code-standards/references/living-docs.md:44`.
- **Guard**: The PreToolUse hook that denies a fixed list of destructive commands (for example `rm -rf`, `git push --force`, `git reset --hard` and `docker compose down -v`). It is a deterministic gate, not a policy engine: local, failing open and never a replacement for user confirmation. The one exception is `git branch -D <one name>`, which passes only when the branch tip is a merged PR's head per `gh`, and that check fails closed (KIT-020). Source: `docs/design.md:40`, `docs/design.md:42`, `docs/design.md:44`, `CONTRIBUTING.md:72`, `plugins/guardrails/hooks/hooks.json:3`.

## H

- **Handoff record**: The record a session leaves when work passes to another session or person: the observed state (`git status --short` and the base-to-HEAD log and diff), one named continuation action, and a completeness check. A consumer repository keeps these records under `docs/sessions/`, written from the `doc-session-handoff.md` template. Source: `plugins/guardrails/skills/session/references/handoff-record.md:2`, `plugins/guardrails/skills/session/references/handoff-record.md:10`, `docs/projects.md:11`.
- **Hook**: A command the agent runs on an event. The plugin's single `hooks/hooks.json` defines three: PreToolUse (the guard), PostToolUse on Edit and Write (runs the project's formatter and linter on the edited file, or `check_spec.py` for a file under `docs/spec/`, and reports findings through exit 2) and SessionStart (warns when the repository sits in a cloud-synced folder and, after a compaction, prints the repository's git state). Hooks load only in local Devin and Claude Code and are best effort. Source: `plugins/guardrails/hooks/hooks.json:15`, `plugins/guardrails/hooks/hooks.json:27`, `README.md:41`, `docs/design.md:12`, `CONTRIBUTING.md:72`.

## K

- **Kit (AI Kit, agent-rules-kit)**: This repository: a plugin-first source of always-on rules, path rules, skills, references and templates for the supported agents. The docs also call it the AI Kit, and its clone on a machine lives at `~/.ai-kit`. Source: `README.md:3`, `plugins/guardrails/AGENTS.md:1`, `README.md:22`.
- **`kit-feature` issue**: The GitHub issue titled `[KIT-NNN] <title>` and labelled `kit-feature` that links a KIT record; the pull request that implements the record closes it. Source: `docs/features/README.md:17`, `docs/features/README.md:18`, `CONTRIBUTING.md:46`.
- **KIT-NNN record**: The file `docs/features/KIT-NNN-<slug>.md`, copied from `docs/features/TEMPLATE.md` once the owner confirms a kit proposal. It is required only for a big change (a hook, `plugins/guardrails/AGENTS.md`, plugin structure or manifests, a check, gate or script behavior, or a new or removed skill); its status runs `confirmed` to `done` or `dropped`. Source: `docs/features/README.md:9`, `docs/features/README.md:14`, `docs/features/README.md:16`, `docs/features/README.md:22`, `CONTRIBUTING.md:46`.
- **Kit proposal**: The single improvement proposal a session may end with: a gap in the kit, or a rule or step to simplify, backed by evidence from the session and asked before it is written. If the owner confirms it, it becomes a KIT-NNN record. Source: `plugins/guardrails/AGENTS.md:15`, `docs/features/README.md:14`, `plugins/guardrails/skills/session/references/kit-proposal.md:2`.

## L

- **Layout freeze**: The layout of 10.x, kept unchanged by 11.0.0, is frozen until at least 2027-01-01: `plugins/`, `platforms/`, `docs/`, the plugin and marketplace manifests and the install destinations. Changing one is a SemVer MAJOR change with a deprecation note and a migration in `bootstrap.sh` and `doctor.sh`; a content change is MINOR or PATCH. KIT-055 records the owner-approved exception, the rename of `plugins/core` to `plugins/guardrails`. Source: `docs/design.md:23`, `CONTRIBUTING.md:40`, `docs/features/KIT-055-plugin-renamed-guardrails.md:57`, `.github/PULL_REQUEST_TEMPLATE.md:8`.

## M

- **Marketplace**: A catalog that a platform reads to discover plugins. The kit ships two, both named `ai-kit` and both listing `guardrails`: `.claude-plugin/marketplace.json` for Claude Code (its `renames` map migrates a retired plugin name to its successor) and `.agents/plugins/marketplace.json` for Codex. Devin needs no catalog: the repository's root meta-plugin requires `guardrails`. Source: `README.md:47`, `.claude-plugin/marketplace.json:2`, `.claude-plugin/marketplace.json:9`, `.agents/plugins/marketplace.json:2`, `README.md:73`, `README.md:65`.
- **Meta-plugin (`agent-rules-kit`)**: The content-free Devin plugin at the repository root (`.devin-plugin/plugin.json`, named `agent-rules-kit`). It carries no rules or skills and only requires `guardrails`, so installing the repository installs the full kit. Source: `.devin-plugin/plugin.json:2`, `.devin-plugin/plugin.json:5`, `README.md:47`, `docs/design.md:7`.

## P

- **Path rule (glob rule)**: A rule file under `plugins/<plugin>/rules/` that loads only when the agent touches a file matching its globs (`globs` on Devin, `paths` on Claude Code; Codex routes by description), so it costs nothing until then. It is a pointer to the owning skill plus a short list of always/never bullets, at most 40 lines; the kit has four: `godot`, `java`, `python` and `spec`. Source: `docs/design.md:17`, `CONTRIBUTING.md:47`, `README.md:41`, `README.md:42`, `README.md:43`, `plugins/guardrails/INDEX.md:41`, `plugins/guardrails/rules/godot.md:3`.
- **Playbook**: A prompt file for a Devin Cloud child session in the review loop, shipped under `platforms/kits/devin/playbooks/` because plugin hooks and subagents do not load in Devin Cloud. There are three: `implement-issue`, `fix-round` and `devin-review-autofix`. Source: `docs/design.md:36`, `platforms/kits/README.md:7`.
- **Plugin**: A directory under `plugins/` with three manifests (`.devin-plugin/plugin.json`, `.claude-plugin/plugin.json` and `plugin.json`) and a generated `INDEX.md`. The kit has exactly one, `guardrails`, in the marketplace `ai-kit`; it holds the always-on rules, the hooks, the path rules, the skills, the subagent profiles, the templates and the evals. Source: `CONTRIBUTING.md:24`, `CONTRIBUTING.md:25`, `README.md:3`, `plugins/guardrails/.devin-plugin/plugin.json:2`.
- **Pre-existing failure**: A failure counts as "pre-existing" only after the same command failed, in the same session, on the commit before the first change (for a PR, its base). A mid-series `main` is no baseline. Source: `plugins/guardrails/AGENTS.md:44`.
- **Profile (repository sync)**: A named set of stacks (`godot`, `java`, `python`, `docs`; `:<dir>` scopes that profile's rule globs to a monorepo folder and a comma list combines several) that decides which skills and rules `sync-project.sh` gives a consumer repository. `platforms/tools/sync-profiles.txt` lists, for each `guardrails` skill and rule, the profiles that receive it, and `check_kit.py` requires exactly one line per entry. Not to be confused with a *subagent profile*. Source: `docs/design.md:9`, `platforms/tools/README.md:20`, `platforms/tools/README.md:19`, `docs/projects.md:16`.

## R

- **Reference**: A file of facts or normative depth owned by one skill, at `plugins/<plugin>/skills/<owner>/references/<topic>.md`. Its frontmatter sets `kind: fact` (with date and sources) or `kind: detail`; it stays within 60 lines and is linked from `SKILL.md`. Source: `CONTRIBUTING.md:49`, `docs/design.md:21`, `platforms/ci/validations/check_kit.py:29`.
- **`refresh.sh`**: Fast-forwards the kit clone's `main` and updates the Codex and Claude marketplaces and plugins, reinstalling a Claude plugin whose cache differs from the kit. On macOS a launchd agent runs it at login and every six hours. Source: `platforms/tools/README.md:6`, `README.md:83`, `platforms/kits/README.md:13`.
- **Regime (spec-first, spec-anchored)**: How a spec artifact ages. Spec-anchored artifacts (schemas, decisions, requirements, journeys, the `spec.md` index) are maintained and validated for the life of the product; spec-first artifacts (FEAT bodies and task tables) are written to cut the work and frozen as history once delivered, their status derived by tooling from GitHub. Source: `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:38`, `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:39`, `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:40`.
- **Release and `VERSION`**: `VERSION` is the single source of the kit version, read by `check_kit.py`, `bump_version.py` and `release.yml`. A release bumps it with `bump_version.py X.Y.Z`, opens a `chore(release): publish X.Y.Z` PR, tags the merge commit `vX.Y.Z` and lets the tag run `release.yml`. Source: `README.md:17`, `CONTRIBUTING.md:33`, `CONTRIBUTING.md:36`, `CONTRIBUTING.md:37`, `CONTRIBUTING.md:38`.
- **Review loop**: The orchestrated implement-review-merge loop that a consumer project can run. The kit ships only its model-free half (the verdict contract and an example config, plus the Devin child-session playbooks and the `kpi.py` report); the model half (orchestrator, reviewer and child skills) lives in the project that runs the loop (KIT-038). Source: `platforms/kits/review-loop/README.md:3`, `docs/design.md:36`, `platforms/tools/README.md:15`.
- **`REVIEW.md`**: A review-criteria file that a consumer repository receives at its root (not in `.github/`). Anthropic's hosted Claude Code Review and any other reviewer, human or agent, read it to know what to flag and what is intended. Source: `platforms/kits/github/REVIEW.md:3`, `docs/projects.md:19`.
- **Review verdict**: The completion verdict `READY`, `PARTIAL` or `NOT READY`, given by skill `review` as SDD step 7 and put in the first sentence of a `reviewer` report. Source: `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:25`, `plugins/guardrails/agents/reviewer.md:27`.

## S

- **SDD (spec-driven development)**: The kit's feature pipeline, adapted from github/spec-kit as repository skills; its artifacts live under `docs/spec/` in a consumer repository, never in the kit. The chain runs step 0 `sdd-constitution`, 1 `sdd-specify`, 2 `sdd-clarify`, 3 `sdd-check`, 4 `sdd-plan`, 5 `sdd-tasks`, 6 `sdd-implement`, 7 `review` and 8 `sdd-to-card`; `sdd-journey` (one user-visible flow) and `sdd-spike` (a prototype lane for game feel) sit beside it. Source: `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:6`, `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:8`, `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:16`, `plugins/guardrails/AGENTS.md:55`, `plugins/guardrails/INDEX.md:31`, `plugins/guardrails/INDEX.md:34`.
- **Session closeout**: The end-of-session summary (done, unverified, a concrete next step) plus at most one *kit proposal*. Skill `session` also covers session start, topic switches and handoffs. Source: `plugins/guardrails/AGENTS.md:15`, `plugins/guardrails/skills/session/SKILL.md:3`.
- **Shared-key frontmatter**: A kit file carries each platform's routing keys together (`triggers`, Codex policy and `disable-model-invocation`; `globs` and `paths`; lowercase and Claude tool names), and `check_kit.py` validates that they agree. Source: `docs/design.md:10`.
- **Skill**: A procedure the agent loads on demand: `plugins/<plugin>/skills/<name>/SKILL.md`, whose frontmatter `description` (with a literal `Use when` and `Not for`) says when to load it, with depth in `references/`. `SKILL.md` stays within 80 lines, and a new skill is only for a topic no existing skill owns (KIT-039). Source: `CONTRIBUTING.md:12`, `CONTRIBUTING.md:48`, `platforms/ci/validations/check_kit.py:28`, `plugins/guardrails/INDEX.md:11`.
- **`smoke.sh`**: Runs `bootstrap.sh` and `doctor.sh` against isolated throwaway homes. Run it after lifecycle changes; the PR checklist lists it. Source: `platforms/tools/README.md:9`, `.github/PULL_REQUEST_TEMPLATE.md:4`.
- **Subagent profile**: A file in `plugins/<plugin>/agents/` that defines a helper agent, with frontmatter (`name`, `description`, `allowed-tools`, `tools`) validated by `agent.schema.json`. The kit has two: `researcher` (read-only research that returns a cited report) and `reviewer` (runs gates and reviews a diff, reports findings and never fixes). Devin CLI/Desktop and Claude Code share the profiles, Devin Cloud uses managed Devins instead, and Codex has none. Source: `CONTRIBUTING.md:13`, `platforms/ci/README.md:7`, `plugins/guardrails/agents/reviewer.md:3`, `plugins/guardrails/agents/researcher.md:3`, `platforms/ci/schemas/agent.schema.json:6`, `README.md:40`, `README.md:42`, `README.md:41`, `README.md:43`.
- **`sync-project.sh`**: Brings a consumer repository in line with the kit: it copies the spec validation files, generates `CLAUDE.md` (which imports `AGENTS.md`), `.claude/settings.json` and `.claude/rules/<plugin>-<rule>.md` for the repo's profile, and, with `--vendor-skills`, the profile's skills. `--check` detects divergence. Source: `platforms/tools/README.md:19`, `docs/projects.md:14`, `docs/projects.md:28`.

## T

- **Template**: A skeleton for a long artifact that a skill links, in `plugins/<plugin>/templates/` with a `spec`, `doc` or `project` prefix (for example `spec-feature.md` or `project-agents-java-spring.md`). The separate `docs/templates/kit-*.md` files shape kit content and live outside every plugin. Source: `CONTRIBUTING.md:51`, `CONTRIBUTING.md:68`, `plugins/guardrails/INDEX.md:53`, `plugins/guardrails/rules/spec.md:12`.

## U

- **User-only skill**: A skill the model may not pick on its own; the user invokes it. It is marked `triggers: [user]` on Devin, `disable-model-invocation: true` on Claude Code and by an `agents/openai.yaml` policy on Codex. Source: `README.md:40`, `README.md:42`, `README.md:43`, `CONTRIBUTING.md:48`.

## V

- **Vendored skills (consumer repository)**: Copies of a profile's skills that a consumer repository keeps in `.claude/skills/`, written by `sync-project.sh --vendor-skills` and recorded in `KIT_MANIFEST.json` with a sha256 per file. A repository that vendors its skills loads them twice on a machine that has the plugin installed. Source: `docs/projects.md:17`, `README.md:79`.
- **Vendor lock**: `platforms/kits/third-party/skills.lock`, which pins each external skill by name, plugin, upstream repository, path, commit SHA, license and verification date. `vendor.sh` regenerates the skill under `plugins/<plugin>/skills/<name>/` with a `VENDOR.md`, and `vendor.sh --check` verifies the result (it fails on a skill without a license file). Today the lock holds `grilling`. Source: `platforms/kits/third-party/skills.lock:1`, `platforms/kits/third-party/skills.lock:2`, `CONTRIBUTING.md:76`, `CONTRIBUTING.md:83`, `plugins/guardrails/skills/grilling/VENDOR.md:7`.

## Terms the repository does not define

- **`DTEC`, `DGME`, `DPRO`**: Namespaces of the decision files under `decisions/` (`DTEC-nnn`, `DGME-nnn`, `DPRO-nnn`). The docs list and number them separately but never expand the abbreviations. Source: `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:30`, `plugins/guardrails/rules/spec.md:14`.
- **`P2-15`**: Cited as the reason for the `AI_KIT_USER_RULES` default of `0`; nothing in the repository says what it stands for. Source: `platforms/tools/doctor.sh:192`.
- **Stratics and `DPRO-011`**: Stratics is named only as the example consumer (`stratics-docs`) and as the project that already runs the review loop; `DPRO-011` is that project's decision for the loop. The kit holds no definition of either. Source: `docs/projects.md:3`, `platforms/kits/review-loop/README.md:3`, `platforms/kits/review-loop/README.md:7`.
