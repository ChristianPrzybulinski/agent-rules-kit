# P2-06 — sync-project.sh vendors skills into .claude/skills with a manifest

Phase: 2 · Repos: kit (agent-rules-kit) · Branch to create: feat/p2-06-sync-project-vendored-skills from main · Depends on: P2-04, P2-09 (skill names final; P2-10 may move skills between plugins, the generator reads the plugin list, never skill names) · Effort: ~6 h

## Goal

Extend `platforms/tools/sync-project.sh` so that, with `--vendor-skills`, it copies every skill directory of the plugins the repo profile enables (the P2-04 list) into `<repo>/.claude/skills/<name>/`, whole (SKILL.md, `references/`, `agents/`, `scripts/`, `VENDOR.md`, `LICENSE.txt`), marks each copy with a `.agent-rules-kit` file (the v6 convention, `CHANGELOG.md:143`), writes `<repo>/.claude/skills/KIT_MANIFEST.json` (kit version, profile, plugin and sha256 per file) and, in that mode, keeps only `core@ai-kit` in the generated `.claude/settings.json`. `--check` verifies the manifest byte for byte and never writes. Measurable result: a godot-profile throwaway repo ends with 21 marked skill directories and a manifest listing 71 files (50 kit files plus 21 markers); the second run changes nothing; a hand-written `.claude/skills/<name>/` without the marker is never read, replaced or deleted; one edited byte makes `--check` exit 1. Today no Stratics repo carries a kit skill (`stratics-docs` has only its own `.claude/skills/review-loop/SKILL.md`; the other two have no `.claude/`).

## Why

- assessment §4.2: the kit reaches agents by symlinks and user-scope plugins; a Claude Code web session, a GitHub Actions runner, a Devin Cloud without the plugin in the org or a collaborator without `bootstrap.sh` runs "without any global rule, skill or hook". The 2026 practice is "the repository carries what the agent needs", including `.claude/skills/`, distributed by commit through an extended `sync-project.sh`.
- assessment §5, skills row: "Devin reads `.claude/skills/` and recommends `.agents/skills/`; Claude Code reads `.claude/skills/`"; kit today: "skills only in the plugin"; verdict "opportunity: a versioned copy in `.claude/skills/` serves both". Devin rows: subagents and hooks of a plugin load only in Devin CLI/Desktop, not in the cloud, so what the cloud child receives must be in the repo.
- assessment §6 A1, fourth bullet: `.claude/skills/` with a versioned copy of the skills the repo uses, marked `.agent-rules-kit` as v6 did; the Devin plugin stays the main route on Devin Cloud, the copy covers Claude Code cloud sessions, the GitHub Action and collaborators without `bootstrap.sh`. §7 N3: the cloud child gets no plugin subagents or hooks, so the always-on surface must travel with the repo.

Otherwise `cp -R "$KIT_DIR/plugins/<plugin>/skills/<name>" "$tmp/<name>"` (`tmp` from `mktemp -d`), write the marker, then `diff -r -q "$tmp/<name>" "$REPO/.claude/skills/<name>"` and only on difference `rm -rf` the old copy and `mv` the new one in (idempotent, no mtime churn). Marker content, one line:

```

```

   Then remove every `<repo>/.claude/skills/*/` that has the marker and is not in the current pair list (`sync: removed .claude/skills/<name> (not in profile)`); never touch a directory without the marker. Tools: only `cp`, `rm`, `mv`, `mktemp`, `diff`, `find`, `shasum`, `python3` (`smoke.sh:9` restricts PATH to `/usr/bin:/bin`); bash 3.2: no `mapfile`, no associative arrays, no `${var,,}`, `docs/maintenance.md:54` quoting trap.
4. Write the manifest through a `python3 - "$REPO/.claude/skills" "$(cat "$KIT_DIR/VERSION")" "$PROFILE" <<'PY'` heredoc that walks every marked directory, hashes every regular file (`hashlib.sha256`, including `.agent-rules-kit`), and writes `KIT_MANIFEST.json` only when the text differs, `json.dumps(..., indent=2, sort_keys=True) + "\n"`:

```json
{
  "KIT_VERSION": "10.1.0",
  "generator": "platforms/tools/sync-project.sh",
  "profile": "godot",
  "skills": {
    "sessions": {
      "plugin": "core",
      "files": {
        ".agent-rules-kit": "<sha256>",
        "SKILL.md": "<sha256>",
        "agents/openai.yaml": "<sha256>"
      }
    }
  }
}
```

   Paths are relative to the skill directory with `/` separators; output depends only on the kit tree, `VERSION` and the profile (no timestamps, hostnames or absolute paths).
