## Goal

Give the kit its first measurement layer: a `claude plugin eval` suite (24 cases, 3 or more per subject, each with a no-plugin baseline arm and 3 runs) for the eight most used skills and the `reviewer` agent, run weekly and on demand by a new `evals.yml` workflow with a pinned model and an uploaded report; and a stdlib-only `platforms/tools/kpi.py` that turns the review loop's `ledger.csv` into per-batch numbers (first-pass approval rate, rounds per PR, share of findings owned by spec, median time to green) with a unit test the kit CI already discovers. Measurable result: `claude plugin eval plugins/<p> --runs 1 --ablation none` loads every case (exit 0 or 1 with no `failed to load` line on stderr; a load error also exits 1, so the exit code alone proves nothing) for the six plugins that gain `evals/`; `check.sh` accepts `evals/` at plugin root and fails on a case without a grader; `python3 platforms/tools/kpi.py <ledger>` prints one line per batch; `docs/maintenance.md` states the targets (first-pass approval >= 60%, spec findings <= 25%) and how both numbers are produced.

It reads the header of step "Current state" and, from the `note` column of `kind=review` rows, space-separated `key=value` tokens: `verdict=<approved|flagged|needs-product|needs-human>`, `findings=<n>`, `spec=<n>` (unknown tokens ignored). Per batch it prints one line: `batch <id>: prs=<n> first_pass_approval=<p>% (<a>/<d>) rounds_per_pr=<mean> (max <m>) spec_findings=<p>% (<s>/<f>) median_time_to_green=<minutes> min`, where: `prs` = distinct `pr` among review rows; first-pass approval = PRs whose earliest review row (by `at`) carries `verdict=approved`, over PRs whose earliest review row carries any `verdict`; rounds per PR = count of review rows per PR; spec share = sum of `spec` over sum of `findings` on rows that carry both; time to green = first review row with `verdict=approved` minus the earliest row (any role or kind) sharing the same `issue`, or the same `pr` when `issue` is empty. A metric with denominator 0 prints `n/a`. Exit 0 on a readable ledger, 2 on a missing file or a header that is not the one above. `--json` prints a list of per-batch objects with the same keys.
