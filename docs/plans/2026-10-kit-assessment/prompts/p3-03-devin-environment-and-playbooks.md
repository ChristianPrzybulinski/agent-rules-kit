# P3-03 — Devin environment.yaml templates and playbooks

Phase: 3 · Repos: kit, stratics-docs, stratics-client, stratics-server · Branch to create: feat/p3-03-devin-environment-and-playbooks from main (one branch per repo, same name) · Depends on: P2-02 (rules carry the critical constraints a Devin Cloud child receives), P2-14 (offline Maven: `dependency:go-offline` must work on stratics-server before the maintenance step can rely on it) · Effort: ~6 h

## Goal

Give the kit a `platforms/kits/devin/` folder that a project copies to run Devin Cloud sessions reproducibly: three `environment.yaml` templates (Godot, Java/Maven, docs), a snapshot checklist, two Playbooks (`implement-issue`, `fix-round`) derived from the stratics-docs review-loop prompts, and a note on combining the DPRO-011 loop with Devin Review autofix. Then add an `environment.yaml` to each of the three Stratics repos from those templates (three PRs). Measurable result: `platforms/tools/check.sh` passes with the new folder registered in `platforms/kits/INDEX.md`; each Stratics repo has a root `environment.yaml` that parses and whose `knowledge` block repeats the repo's DoD commands byte-for-byte; the two Playbooks contain zero owner names, repo names or `{ISSUE}`/`{REPO}` tokens (only `<placeholders>`).

## Why

- assessment §7 item N3: the kit has no `environment.yaml` template, no snapshot checklist and no Playbooks, while the review loop's Devin children run today from `devin-child-implement.md` / `devin-child-fix.md` pasted by hand (stratics-docs `ops/review-loop/prompts/`, see Current state).
- assessment §5, row "Devin ambiente": Devin expects a snapshot plus `environment.yaml` (`initialize`, `maintenance`, `knowledge`) with lint and tests at 5 min or less each; the kit verdict is "absent".
- assessment §5, row "Devin Knowledge": Knowledge is deprecated and migrates to skills in plugins, but Playbooks remain documented with an API (`playbook_id`); the kit's `docs/design.md:32` still says "Playbooks were left out", which is wrong for Devin Cloud children that receive a pasted prompt (that is exactly a Playbook).
- assessment §5, row "Devin plugins" and §9.2 (confirmed 2026-10-06 on docs.devin.ai): plugin hooks and subagents load only in Devin CLI/Desktop, not in the cloud; one skill is active at a time; `AGENTS.md` and `rules/` of the plugin are always-on. So the only kit content a cloud child is guaranteed to receive is `plugins/core/AGENTS.md` plus the glob rules; today those rules are pointers (`plugins/dev-godot/rules/godot.md:14`, `plugins/dev-java/rules/java.md:12`), which P2-02 fixes.
- assessment §5, row "Devin Review + autofix": autofix must answer only `devin-ai-integration[bot]` to avoid loops; the combination with the Claude-reviewed DPRO-011 loop is undocumented.
- Measured: the three Stratics repos have no `environment.yaml` and no `.devin/` folder except stratics-docs (`ls environment.yaml` fails in all three; stratics-docs `.devin/config.json:5` allows writes only under an absolute path on the owner's Mac, which Devin Cloud never has).
