## Goal

Give the kit a `platforms/kits/devin/` folder that a project copies to run Devin Cloud sessions reproducibly: three `environment.yaml` templates (Godot, Java/Maven, docs), a snapshot checklist, two Playbooks (`implement-issue`, `fix-round`) derived from the stratics-docs review-loop prompts, and a note on combining the DPRO-011 loop with Devin Review autofix. Then add an `environment.yaml` to each of the three Stratics repos from those templates (three PRs). Measurable result: `platforms/tools/check.sh` passes with the new folder registered in `platforms/kits/INDEX.md`; each Stratics repo has a root `environment.yaml` that parses and whose `knowledge` block carries exactly these DoD lines, not the stale `AGENTS.md` lines of stratics-docs and stratics-client: Godot: `godot --headless --path . --import` and `godot --headless --path . -s addons/gdUnit4/bin/GdUnitCmdTool.gd -a res://tests -c --ignoreHeadlessMode` (CI `reusable-ci-godot.yml:92` and `:106` without its trailing ` \` continuation; `:107` only pipes to `tee`); docs: `CI=1 python3 .github/spec-lint/check_spec.py docs/spec .github/spec-lint/schemas` (`docs-checks.yml:78`, keep `CI=1`: `check_spec.py:108-109` turns missing deps into a failure) and `python3 tools/spec-trace/spec_trace.py check` (`:80`); server: `./mvnw spotless:check verify` (stratics-server `AGENTS.md:36` without its trailing comment; CI `reusable-ci-java.yml:70` in stratics-docs only adds `-B -ntp`); the two Playbooks contain zero owner names, repo names or `{ISSUE}`/`{REPO}` tokens (only `<placeholders>`).

## Why

- assessment §7 item N3: the kit has no `environment.yaml` template, no snapshot checklist and no Playbooks, while the review loop's Devin children run today from `devin-child-implement.md` / `devin-child-fix.md` pasted by hand (stratics-docs `ops/review-loop/prompts/`, see Current state).
- assessment §5, row "Devin environment": Devin expects a snapshot plus `environment.yaml` (`initialize`, `maintenance`, `knowledge`) with lint and tests at 5 min or less each; the kit verdict is "absent".
- assessment §5, row "Devin Knowledge": Knowledge is deprecated and migrates to skills in plugins, but Playbooks remain documented with an API (`playbook_id`); the kit's `docs/design.md:32` still says "Playbooks were left out", which is wrong for Devin Cloud children that receive a pasted prompt (that is exactly a Playbook).
- assessment §5, row "Devin plugins" and §9.2 (confirmed 2026-10-06 on docs.devin.ai): plugin hooks and subagents load only in Devin CLI/Desktop, not in the cloud; one skill is active at a time; `AGENTS.md` and `rules/` of the plugin are always-on. - assessment §5, row "Devin Review + autofix": autofix must answer only `devin-ai-integration[bot]` to avoid loops; the combination with the Claude-reviewed DPRO-011 loop is undocumented.
- Measured: the three Stratics repos have no `environment.yaml` and no `.devin/` folder except stratics-docs (`ls environment.yaml` fails in all three; stratics-docs `.devin/config.json:5` allows writes only under an absolute path on the owner's Mac, which Devin Cloud never has).
