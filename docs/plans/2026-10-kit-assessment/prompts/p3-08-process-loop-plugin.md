# P3-08 — process-loop plugin from the DPRO-011 review loop

Phase: 3 · Repos: kit (agent-rules-kit), stratics-docs · Branch to create: feat/p3-08-process-loop-plugin from main (one branch per repo, same name; two separate PRs) · Depends on: P1-08 (task template and issue-per-task flow the loop assumes), P2-10 (plugin registration pattern and the decision on what `all` bundles) · Effort: ~8 h

## Goal

Turn the architect-to-executor-to-reviewer flow that the Stratics review loop (DPRO-011) already runs into kit content: a new plugin `plugins/process-loop` with four skills (orchestrator, reviewer, child implement, child fix), two templates, and a ready-to-copy kit `platforms/kits/review-loop/` holding the verdict schema and an example config with no machine-specific path. Measurable result: a second project, or a second collaborator, can start the loop from kit files only (the project supplies its loop tool and a filled `config.json`); stratics-docs' `.claude/skills/review-loop/SKILL.md` becomes a pointer to the plugin skill; every kit gate stays green with the description budget at or under 7,200 characters.

## Why

- assessment §4.8: what accelerates the project today is DPRO-011 (`loop.py` 1,343 lines, model-free gates, verdict JSON bound to a SHA, waves, model directive per complexity, Devin child prompts, cut checklist); none of it is in the kit, which has only `parallelize` (54 lines, `plugins/core/skills/parallelize/SKILL.md`) and `sdd-to-card`.
- assessment §7 item N4: a `process-loop` plugin with the parameterized orchestrator prompt (no absolute paths), verdict schema, proof allowlist, round policy (2 flagged rounds, then `needs-human`), ledger and batch report is "the content with the most leverage for a second project or a second collaborator".
- assessment §5, multi-agent row: writes single-threaded, extra agents contribute intelligence (research, review), not actions; "writer plus independent reviewer" is the pattern that works (Cognition "Don't Build Multi-Agents" 2025-06 and "Multi-Agents: What's Actually Working" 2026-04; Anthropic `sub-agents` docs and the adversarial review pattern in `best-practices`: a reviewer that sees only the diff and the criteria). DPRO-011 implements exactly that (Devin writes, Claude reviews, `loop.py` merges), "but the loop lives outside the kit".
- stratics-docs `docs/spec/decisions/DPRO-011-orchestrated-review-loop.md:132`: `[FACT] 20 of the 33 PRs the architect reviewed up to 2026-10-05 (61%) were flagged on the first pass: light 1 of 4, standard 10 of 14, full 9 of 15.` The review rules that caught those defects exist only in `ops/review-loop/prompts/claude-orchestrator.md`.
- The orchestrator prompt is machine-bound: `ops/review-loop/prompts/claude-orchestrator.md:6` hard-codes `L=<absolute path under the owner's home>/ops/review-loop/loop.py` ("Always call it by this absolute path") and `:11` a `git -C <absolute clone path> pull`; `ops/review-loop/config.json:6,10,14` hold absolute clone paths under the owner's home and `:105` an absolute `JAVA_HOME`. Nobody else can run it as written.
