# What lives in a project that uses the kit

Rules, skills and knowledge stay **in the kit** and are installed on the machine (`platforms/install/`). The project only receives its own artifacts. Real example: `~/Documents/GitHub/stratics-docs`.

## In the project

| Artifact | Origin in the kit | Example (stratics-docs) |
|---|---|---|
| repo `AGENTS.md` | `kit/templates/project-agents-*.md` filled in | `AGENTS.md` (scope, commands, boundaries) |
| `docs/spec/` | created by `platforms/kits/sdd/init-spec.sh`; artifacts follow `kit/templates/spec-*` and `platforms/ci/schemas/` schemas | `docs/spec/spec.md`, `features/FEAT-0nn.md`, `requirements/`, `decisions/`, `debts/` |
| `docs/sessions/` | `kit/templates/doc-session-handoff.md` | `docs/sessions/2026-09-30-initial-specs.md` |
| `docs/legacy/` (or reports) | `kit/templates/doc-*.md` | `docs/legacy/evidence.md` etc. |
| `.github/spec-lint/` | copy generated by `platforms/tools/sync-project.sh` (`check_spec.py` + schemas + `KIT_VERSION`) | local spec validation in the project's CI |
| `.github/workflows/` | `platforms/kits/github/workflows/` | `spec-lint.yml` (runs the local copy — no kit checkout/token), `gitleaks.yml`, `reusable-ci-*.yml` |
| `.github/PULL_REQUEST_TEMPLATE.md`, `CODEOWNERS`, `dependabot.yml`, labels | `platforms/kits/github/` | ditto + `scripts/labels-sync.sh` |
| `infra/` / compose | `platforms/kits/docker/` | `infra/compose.yml` (`name: stratics`) |
| `.gitattributes` (LFS) | `platforms/kits/git-lfs/` | the repo's first commit |

IDs in `docs/spec/`: `FEAT-nnn`, `REQ-F-nnn`, `REQ-NF-nnn`, `DEC-nnn`, `DEBT-nnn` — sequential numbering, `id` = the file name's prefix, status in frontmatter (`proposed`/`approved`/`delivered`…). Process: `kit/skills/sdd-constitution/references/sdd-process.md`.

## What does NOT go to the project

- Skills (including the normative rules, now under `kit/skills/`) and knowledge: installed on the agent's machine — the project does not copy them.
- Spec schemas and validators reach the project as a **deliberate copy** in `.github/spec-lint/` (no link to the kit in CI — the kit repo may not even exist at CI time). Update: `sync-project.sh <repo>`; divergence detectable with `sync-project.sh --check`. Reusable workflows **between repos of the same product** (e.g.: `stratics-client` → `stratics-docs/.github/workflows/reusable-ci-*.yml`) are allowed — what is avoided is depending on the kit.
- Legacy archive originals: only reports/manifests enter the repo (project rule, see stratics-docs' `docs/legacy/README.md`).
