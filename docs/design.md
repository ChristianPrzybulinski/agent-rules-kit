# Design — why the kit is like this

The validated layout and routing test live in [`../INDEX.md`](../INDEX.md). These principles explain the choices behind them.

## Principles

- **Single source: `plugins/` is the plugin family root.** The repository root follows Cognition's team-marketplace pattern: a content-free meta-plugin requires the `all` bundle through `git-subdir` (install repo = full kit) and lists every content plugin as optional for minimal installs via `#plugins/<name>`. Each plugin directory is consumed directly by Devin, Codex and Claude Code; there is no generated distribution tree.
- **One content tree, three agent families.** Skills, rules, agents and templates are shared across Devin, Codex and Claude Code; per-platform manifests (`plugins/<name>/.devin-plugin`, `.claude-plugin`, `plugin.json`) adapt discovery and dependencies without copying content.
- **Dependency graph, not duplication.** Satellites declare their parent through `requiredPlugins` (Devin) / `dependencies` (Claude): `dev-java`→`dev-core`→`core`. The `all` bundle is manifest-only and resolves to every plugin except the opt-in `extras` (frontend design, Krita, DBeaver, skill discovery and skill authoring), which is installed explicitly. Plugin names double as the taxonomy: `family-name`.
- **Shared-key frontmatter.** A file carries each platform's routing keys together: `triggers`/Codex policy/`disable-model-invocation`, `globs`/`paths`, and lowercase/Claude tool names are validated for parity.
- **One hook file.** `hooks/hooks.json` uses Claude's wrapper because both local Devin and Claude Code load it; one command and one case table prevent security drift. The commands stay inline in `hooks.json`: a script needs the plugin root, Claude Code exports `CLAUDE_PLUGIN_ROOT` to plugin hooks but a Devin run was never verified, and a script that is not found exits with a code other than 2, so the guard would fail open (KIT-040).
- **Formatting runs in a hook, not in instructions.** A PostToolUse hook on Edit and Write runs the project's formatter and linter on the edited file (gdtoolkit, google-java-format, the synced spec validator) and reports findings through exit 2 so the agent sees them before the next step. It fails open when a tool is absent, never blocks, and stays in the same `hooks.json` with its own case table. Stop and UserPromptSubmit remain excluded (see below).
- **A repository in a cloud-synced folder gets a warning, not a block.** A SessionStart hook (matcher `startup`) resolves the working directory and names the iCloud, File Provider, Dropbox or OneDrive folder it sits in; `sync-project.sh` reruns the same hook command for its target repository, so the detector exists once and also reaches Codex users. Some people sync on purpose, so it never blocks.
- **Plugin-first on every surface.** Devin Cloud and local Devin consume the repository plugin; Codex and Claude Code consume their marketplace plugins. Machine setup adds only zero-copy instruction/rule symlinks and the temporary Codex compatibility fallback.
- **Minimal always-on context.** `AGENTS.md` keeps only durable routing and boundaries. Procedures and detail load through skills or triggered rules instead of consuming every message.
- **Always-on test.** A line stays in `AGENTS.md` only if the behavior must hold before any skill could trigger—session start, response shape, safety stops or boundaries. Everything else is a skill or a glob rule.
- **Glob over `model_decision`.** A glob rule costs nothing until a matching file is touched; a `model_decision` rule contributes its description on every message. Use it only when no reliable glob exists.
- **Content/tooling separation.** `plugins/*/` contains only plugin manifests and model-facing content; `platforms/`, `docs/` and repository automation stay outside the plugin root.
- **Zero content copies on the machine, one versioned copy per repository.** On a machine, agent-facing content is reached through plugin caches or symlinks. This prevents duplicate skill names and drift between installed copies. A consumer repository may carry a generated, version-stamped copy of path rules, spec validators and skills (`sync-project.sh`, `--check` detects drift); that copy is a commit, not a machine copy, and it is what cloud sessions, CI runners and new machines load. On a machine where `doctor.sh` also keeps the `~/.claude/rules/` symlinks (`AI_KIT_USER_RULES=1`, today's default) a rule present in both places loads twice; set `AI_KIT_USER_RULES=0` there (P2-15 flips the default once the consumer repos carry `.claude/rules`).
- **Description budget is a hard gate.** Codex budgets about 8,000 characters for the initial skill list, so the kit reserves at most 7,200 for all skill descriptions.
- **One owner per detail.** A rule routes, a skill executes, a reference holds facts or normative depth, and a template supplies shape. Cross-links replace copied paragraphs.
- **Everything validatable.** Layout, manifests, frontmatter, budgets, indexes, links and vendor locks are mechanical CI gates.
- **Layout stability.** The layout of 10.x, kept unchanged by 11.0.0, is frozen until at least 2027-01-01: `plugins/`, `platforms/`, `docs/`, the plugin and marketplace manifests (`.devin-plugin/`, `.claude-plugin/`, `plugin.json`, `.agents/plugins/`) and the install destinations (`~/.ai-kit`, `~/.codex/AGENTS.md`, `~/.claude/CLAUDE.md`, the marketplace plugin caches) keep their paths. A path or destination change is a SemVer MAJOR release and ships with a deprecation note in `CHANGELOG.md` and a `doctor.sh` migration; content changes are MINOR or PATCH. Consumer repositories cite kit paths, so `sync-project.sh --check` fails on citations of removed layouts.

## Codex compatibility fallback

Plugin skills remain installed but may be absent from the model input while [openai/codex#22078](https://github.com/openai/codex/issues/22078) is open. `doctor.sh` probes for `<plugin>:*`; while absent, it maintains skill symlinks from `~/.codex/skills/` to `~/.ai-kit/plugins/*/skills/`, and removes them once the plugins expose the skills. If that directory proves unreadable, the documented one-time administrative fallback is `/etc/codex/skills` pointing to the repository skills. This is a measured compatibility exception, not a second source.

## What was left out, and why

- **Windsurf, Cursor and ChatGPT destinations were left out:** they are outside the initial v6 surface. Windsurf directories were also imported by Devin and helped triple the observed startup context.
- **`~/.agents/skills` for Codex was left out:** Devin reads that location too, producing duplicates beside plugin skills. The fallback uses the Codex-only directory instead.
- **A second skills copy in `.agents/skills` was left out:** Devin also scans `.claude/skills`, so one directory serves Claude Code and Devin; generating both would load every skill twice.
- **Knowledge notes as `model_decision` rules were left out:** each rule description would tax every message. Notes now live as references owned by the skill that needs them.
- **A built `devin-plugin` branch was left out:** `main` itself is the release and the plugin source.
- **Playbooks are kept only for Devin Cloud children:** plugin hooks and subagents do not load in Devin Cloud, so the review-loop child prompts ship as `platforms/kits/devin/playbooks/*.devin.md`; user-invoked skills cover the same procedures on every other surface.
- **Knowledge was left out:** Cognition deprecated it; references now live under the skill that owns and loads them.
- **MCP servers were left out:** tool schemas cost context on every turn, while `gh` covers the GitHub operations this kit needs.
- **Stop and UserPromptSubmit hooks were left out:** Stop can loop, and UserPromptSubmit spends tokens on every turn.
- **The PreToolUse guard is a deterministic gate for a fixed list, not a policy engine.**
  - What must hold every time goes in a hook; a skill or `AGENTS.md` sentence is advisory (Claude Code best-practices).
  - Covered, anchored at each command segment including after `sudo`/`xargs`/`time`/`env`: `rm -rf`, `find -delete`, `git push --force`, `git branch -D`, `git checkout -- <path>`, `git restore` (unless `--staged`), `git reset --hard`, `git clean -f`, `git stash drop`, `git filter-repo`, `git lfs migrate`, `docker compose down -v`, `docker prune`, `docker volume rm`, `flyway clean`, `destructive SQL file` (file name contains `drop|trunc|clean|reset|wipe|purge|destroy`), `destructive SQL`, `terraform destroy`, `gh repo delete`, `truncate -s 0` (size 0 only), `chmod -R 777` (recursive only), `curl | sh`.
  - Not covered, relies on the instruction: `git checkout <ref> -- <path>` (overwrites one path), `git worktree remove --force`, `UPDATE`/`DELETE` without `WHERE` (`dbeaver` skill), adding or removing a dependency and changing an applied migration (`plugins/core/AGENTS.md`), deploy/e-mail/payment side effects, anything typed by a human, Devin Cloud sessions (no hooks), and SQL files whose name does not contain a destructive word.
  - The guard is local, fails open and never replaces user confirmation: `docs/maintenance.md` keeps that statement.
- **`security-guidance` was left out as a kit dependency:** it reviews edited code for vulnerability patterns and does not block commands, so it cannot replace the PreToolUse guard; a project may enable it beside the kit as a Claude-Code-only code-security complement through the generated `.claude/settings.json` (the file P2-04 generates; not enabled by default).
- **Additional skill frameworks were left out:** markdown procedures avoid another runtime and remain portable across supported agents.
- **A `.devin/rules` copy was left out:** the Devin plugin already loads `plugins/*/rules/` by glob from the plugin itself; a second copy would load twice.
