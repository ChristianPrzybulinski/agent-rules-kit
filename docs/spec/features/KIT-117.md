# KIT-117 — Require an evidenced why chain on fix and improvement PRs, checked as a WARN

## Problem and evidence

[FACT] The owner rule, relayed by the principal session on 2026-11-22 in
[#444](https://github.com/ChristianPrzybulinski/agent-rules-kit/issues/444), asks that improvements use the five whys.
The issue identifies the gap: `investigate` asks for a named cause and rejects symptom-hiding guards, but neither
the PR templates nor `review_checks.py` asks for the chain from symptom to the cause the fix removes.

[FACT] #444's Stratics example reports spec PRs #5404, #5406 and #5435 failing `link`, `scope` and `proof-declared`:
no `Closes` line → no planning issue → an architect opened the spec PR directly → no planning-issue checklist step
→ `sdd-plan` assumes every PR starts from an issue. The issue cites REST bodies (2026-11-22) for the missing lines
and #5404's gate record at 32297a2 for issue 5461 created after the fact. Gate names and whys 3–5 are explicitly
relayed evidence, not failing runs re-verified here; later gate records passed after repair. The example's fix adds
the planning-issue step; a later spec PR reaching the gates without `Closes` would refute it.

## Scope

- `platforms/tools/review_checks.py`: `whys --body PR.md --title TITLE [--issue-labels LABEL ...]`, using
  `pr_gates.sections` and `Findings`, ignoring HTML comments so the optional scaffold is not a chain; command usage in the module docstring.
- `platforms/ci/validations/test_review_checks.py`: `WhysTest`, written and run red before the implementation.
- `.github/PULL_REQUEST_TEMPLATE.md` after Red and `platforms/kits/github/PULL_REQUEST_TEMPLATE.md` after Proof:
  HTML-commented Five whys fields, allowed exemptions and the ceiling of five.
- `plugins/guardrails/skills/investigate/SKILL.md` § 5: report the cause as the evidenced why chain.
- `plugins/guardrails/skills/sdd-implement/references/task-pr.md`: fix rows and bug-closing PRs carry the section
  or exempt line; the command warns otherwise.
- `plugins/guardrails/skills/session/references/kit-proposal.md`: Evidence carries the chain for a bottleneck or fix.
- `plugins/guardrails/skills/review/references/delivery-steps.md`: run Whys and report its non-blocking warning.
- `docs/spec/features/KIT-117.md`, `docs/spec/spec.md` and `CHANGELOG.md`: this record, its index and Unreleased entry.

## Out of scope

- [DECISION] No CI or project workflow wiring, promotion to FAIL, or label fetching inside the command. Callers
  supply labels. Measuring the WARN and any later promotion require a follow-up.
- [DECISION] No edits to `review/SKILL.md`, which is already at its 80-line cap.

## Plan

### Tests

[DECISION] Write `WhysTest` first and preserve its failing command output in the PR's Red section. Run it green,
then the full affected test file, the size proof, index generation and both required gates. Run the existing
`investigate-trigger-slow-job` eval; no `sdd-implement` case covers these lines. Check this PR's own complete chain.

### Risks

[DECISION] #444's falsifier: two weeks after release, sample at least 10 in-scope PRs carrying the section. If most
Root cause fields restate the symptom or why 1, or the Fix removes why 1 instead of the root cause, the section has
become ritual and the rule falls back to skills only. Keep the check a WARN until measured; five is a ceiling,
never a quota. The check proves shape and evidence presence, not the truth of a claimed cause.

## Decisions

- [DECISION] 2026-11-22 (#444): follow the owner's approved middle option: a template plus non-blocking check.
  Skills alone depend on discipline; a FAIL on every PR risks padded chains and false-positive blocks.
- [DECISION] 2026-11-22 (#444): normalize the Stratics narrative into the required fields for its test, preserving
  attribution for the relayed evidence rather than presenting it as independently verified.
