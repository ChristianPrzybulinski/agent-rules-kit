# KIT-112 — Read each OWNER/NAME#N issue in its own repository

## Problem and evidence

[FACT] The owner said on 2026-11-17, in a Claude Code session on `dev-game-studio/review-loop`, after the choice between
two backlog repositories was explained: "mas precisamos uma solucao melhor, saber por repositorio onde procurar" (issue
#387, kit 17.1.0, `8eb3c0a`).

[FACT] `spec_trace.py sync-status` reads one backlog repository. At base `a214792`, `item_issue` accepts `#N`, or
`OWNER/NAME#N` only when `OWNER/NAME` is `sdd.github.repo` or one of `sdd.github.aliases`; any other repository returns
`None`, so the row counts as having no issue. `task_issues` lists the issues of that one repository, and `closing_prs`
honours a bare `Closes #N` inside the backlog only. An alias is an earlier name of the same repository.

[FACT] A spec whose rows point at two repositories cannot sync. `dev-game-studio/review-loop` moved out of
`dev-game-studio/stratics` on 2026-11-16: its older FEATs cite issues that live in Stratics (FEAT-053 has 27 bare `#N`
Item cells), its new work lives in its own repository (review-loop#101 onwards). Read-only runs of
`spec_trace.py sync-status docs/spec` on 2026-11-17: with the backlog `dev-game-studio/stratics` the older rows find
their issues (`FEAT-125 T1: todo -> cancelled (closed as not planned)`) and nothing in review-loop is seen; with
`--backlog dev-game-studio/review-loop` the same rows read `FEAT-125 T1: todo (no issue)`. Issue number 101 exists in
both repositories, so one bare `#101` cannot name both.

[DECISION] Type: platform; route: feat-only; size: S; confirmed by: the go-ahead on the open-issue review, 2026-11-19.
Items 1 to 4 of the issue's proposed text: no new key, and a spec with one repository and bare `#N` cells syncs exactly
as today. Composes with KIT-106: a FEAT with a canonical `issue` keeps its row states and reads no row's repository.

## Scope

- `platforms/ci/validations/spec_trace.py`: `item_issue` returns `(repository, number)` (a bare `#N` is the backlog,
  `OWNER/NAME#N` that repository, an alias the backlog); `sync_status` lists the backlog once and each other repository
  named by the Item cells of the rows it syncs once (`row_repositories`), keys each lookup by repository and reads a row's
  issue in its own; `closing_prs(..., by_issue=True)` keys PRs by `(repository, number)`, a `Closes OWNER/NAME#N` naming
  that repository (an alias, the backlog) and a bare `Closes #N` the PR's own repository, and its default result stays
  the backlog's `{number: PRs}`; `feat_prs` looks up its FEAT's `issue` as `(backlog, number)`.
- `platforms/ci/validations/test_spec_trace_sync_status.py`: nine tests added, none changed.
- Follow-up (#413, 2026-11-19), same files: a repository whose issues `gh` cannot list freezes its rows (`unread_warning`
  names the repository, the reason, the rows with the issue each cites, the consequence and the fix) instead of reading
  the backlog issue that shares their title; `closing_prs` names a non-backlog `pr_repos` repository it cannot list;
  repository names compare without case (`repo_key`, `known_repos`) in `item_issue`, `row_repositories`, `closing_prs`,
  `sync_status` and `feat_prs`. Eight tests added and the one `other/repo#11` test changed (it pinned the fallback).
- `plugins/guardrails/skills/sdd-constitution/references/sdd-parameters.md`: the `github` row says `repo` is the default
  for a bare `#N` and a full reference is read in its own repository.
- `CHANGELOG.md`, `docs/spec/spec.md` and this record.

## Out of scope

- A FEAT's own `issue` or `pr` field naming a repository outside the backlog and `pr_repos`: `feat_prs` still warns
  `is outside the backlog repositories`.
- Reading the pull requests of a repository only because a row cites it: `closing_prs` still lists the backlog and
  `pr_repos`, so a project lists the other repository in `pr_repos` (as the issue says).
- A `repos: [...]` list for bare `#N`, running `sync-status` once per repository, and the `profile.schema.json`
  descriptions of `repo` (rejected or left in #387; no new key).
- Skill text outside the `github` row of `sdd-parameters.md`: `sdd-tasks`, `sdd-check`, `sdd-clarify`, `sdd-plan`,
  `sdd-intake` and `sdd-specify` belong to other changes.

## Plan

### Tests

[FACT] Nine tests are added to `SyncStatusTest` and none of the 42 existing tests changed (`gh` is the canned stub of
that file; no test calls the network). On base `a214792` six of them failed (eight failures, four of them subtests of one test, and one error): the
`item_issue` tuples, the full-reference and bare `Closes` keys of `closing_prs(by_issue=True)`, the two-repository run
with issue 11 in both, the once-per-repository listing, the unreadable repository and the canonical-FEAT-beside-a-
cross-repository-row case. The backlog-only bare close, the alias and the unreadable backlog tests passed before the
change by design: they pin behavior that must not move. The existing `other/repo#11` fallback test and the `result[11]`
assertion of the earlier-name test pass unchanged.

### Risks

- [HYPOTHESIS] A transferred issue that `gh` cannot reach by its old `OWNER/NAME#N`: GitHub redirects a transferred
  issue, but this was not tested. Untested here too: the listing of the old repository does not contain it, so its row
  would read `no issue` (or fall back to its title) until the Item cell names the new repository.
- A cell naming a repository the token cannot read costs one more listing (a `WARN`, never a stop); before, such a
  cell was ignored without a call. A mistyped repository costs one call and one warning per run, and its rows stay as
  they are until the cell is corrected.
- An unreadable non-backlog issue repository leaves the rows that cite it as they are (the `WARN` names them) and does
  not stop the run; the backlog and any `pr_repos` repository still stop it, because any row may depend on their data.
  A project that runs `sync-status` only in CI therefore sees the stale rows only in the log: a row frozen this way is
  not a failure, so someone has to read the `WARN`.
- A project whose PRs live in the repository its rows cite must list it in `pr_repos`; otherwise its rows stay `todo`
  with no PR evidence.

## Decisions

- 2026-11-19 (issue #387): chose reading each cell in its own repository over several backlog repositories for a bare
  `#N` (`#101` would match the wrong issue), over one `--backlog` run per repository (each run marks the other's rows
  `no issue` and `--write` fights over the same files) and over doing less (the other repository's rows stay `no issue`
  forever).
- 2026-11-19: an unreadable non-backlog repository is a `WARN` and a title fallback, not a stop, so a row citing a
  repository the token cannot see does not block the backlog's rows; the existing test of an `other/repo#11` cell
  without a canned route pins that. The fallback half is superseded by the next decision.
- 2026-11-19 (issue #413): chose to keep the rows of an unreadable non-backlog repository as they are, over the title
  fallback (a backlog issue titled like the row, open with no label, moved a `doing` row to `todo`: reproduced before
  the change) and over stopping the run (one repository the token cannot see would block every other row). The line
  is a `WARN` and the exit stays 0: the rows are in doubt, not wrong. `closing_prs` keeps stopping for a repository it
  cannot list because no row can be ruled out; it now names the repository and where to change it. Would prove the
  pick wrong: a project that needs a failing exit for a frozen row (then the exit code, not the rows, changes).
- 2026-11-19 (issue #413): repository names compare without case (GitHub's own rule). A repository the profile names
  is read under the profile's spelling, any other as the cell writes it; `closing_prs(by_issue=True)` keys use the
  lower-case name. The spec's text is never rewritten.
- 2026-11-19: `closing_prs` keeps its default `{number: PRs}` result for the backlog and takes `by_issue=True` for the
  `(repository, number)` map, so a caller that read the number-keyed map is unchanged.
