# KIT-107 — Leave generated output out of the red check's code roots

## Problem and evidence

[FACT] `review_checks.py red` reports `red: NONE` (exit 1) when the only production change under `--code-roots` is
generated code that a separate check already proves. `red_select` keeps every non-test path that matches
`--code-roots` (`platforms/tools/review_checks.py`, the `code` list), and a glob cannot subtract paths. In
dev-game-studio/stratics#4337 (head `e15367861`) the only server change was the protocol-gen output
`MessageTypes.java` and `ErrorCode.java`, which `gen.py --check --all` proves; `red-server` failed with NONE and the
merge needed the owner's override. Five more open contract PRs change the same generated files (#4336, #4338, #4345,
#4459, #4465). Source: issue #400.

## Scope

- `platforms/tools/review_checks.py`: `red` takes `--exclude GLOB` (repeatable). A non-test path under the code roots
  that matches an exclude glob is not production code for the check; the run prints
  `red: excluded N generated path(s) by --exclude: <paths>`, so a reviewer sees what was left out. A PR whose only code
  change is excluded reports `red: EXEMPT`. `--plan` and `--sides-from` share the selection, so the plan reports
  `status: exempt`. Without `--exclude` nothing changes.
- `platforms/ci/validations/test_review_checks.py`: four tests (CA-1 to CA-4).
- `CHANGELOG.md`: one line citing `KIT-107`.

## Out of scope

- A `generated` list in the `--gates` config: the flag is enough for the Stratics row, and a config key would need a
  schema change in `pr_gates.config_errors`. Reconsider if a second project repeats the same globs.
- The Stratics `red-server` row itself (`--exclude` on its command): a change in that repository after the release.

## Acceptance criteria

| ID | Given | When | Then | Proof |
|---|---|---|---|---|
| CA-1 | a PR whose only change is `gen/Types.py` | `red --exclude 'gen/**'` runs | it names the excluded path and prints `red: EXEMPT`, exit 0 | `python3 platforms/tools/run_tests.py platforms/ci/validations/test_review_checks.py` |
| CA-2 | the same PR | `red` runs without `--exclude` | `red: NONE`, exit 1 | `python3 platforms/tools/run_tests.py platforms/ci/validations/test_review_checks.py` |
| CA-3 | a PR that changes `gen/Types.py` and a hand-written `calc.py`, no test | `red --exclude 'gen/**'` runs | the hand edit still counts: `red: NONE`, exit 1 | `python3 platforms/tools/run_tests.py platforms/ci/validations/test_review_checks.py` |
| CA-4 | the CA-1 PR | `red --exclude 'gen/**' --plan OUT.json` runs | `OUT.json` has `status: exempt` | `python3 platforms/tools/run_tests.py platforms/ci/validations/test_review_checks.py` |

## Plan

### Tests

Four tests in the red class of `test_review_checks.py`, one per criterion, on the throwaway repository the class
builds. CA-3 is the falsifier: a generated change must never hide a hand edit.

### Risks

- A glob wider than the generated files hides a hand edit in the same folder. The excluded paths are printed on every
  run, and the project owns the glob, as it owns `--code-roots`.
- The proof of generated output moves to the project's generator check. If that check is not required, an excluded file
  is proven by nothing; the project's `red` row should only exclude what its generator check covers.

## Decisions

- 2026-11-19 (issue #400): chose a command-line `--exclude` over a `generated` key in the gates config, because the
  flag needs no schema change and the issue named both as acceptable.
