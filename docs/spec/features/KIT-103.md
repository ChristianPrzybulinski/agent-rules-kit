# KIT-103 — Name every spec record file by its id alone

## Problem and evidence

[FACT] The owner wants each spec id in an issue, PR, commit message or release to open its record in one click, through
GitHub's autolink references (repository Settings, Autolink references). An autolink puts only the reference number in
its target URL (`<num>`), so prefix `DGME-` and target `.../docs/spec/decisions/DGME-<num>.md` reach `DGME-001.md` but
never `DGME-001-servidor-autoritativo.md` (GitHub Docs, "Configuring autolinks to reference external resources",
read 2026-11-17). Request, owner, 2026-11-17, Claude Code chat: "acho que temos que padronizar entao pros dgme, dtec,
dpro e need poderem ter. tirando o texto e mandando só o ID", then, on the journey rename: "Sim, sem o JOURNEY".

[FACT] The kit tells every project to name records `<PREFIX>-nnn-slug.md`: 28 lines in 19 files outside
`docs/features/` and `CHANGELOG.md` (`git grep -n -E 'nnn-slug|nnn\[-slug\]|000-slug|NNN-<slug>|0nn-slug'` at
7c3180a), among them `plugins/guardrails/skills/sdd-intake/SKILL.md:28` ("Create `docs/spec/needs/NEED-nnn-slug.md`")
and `plugins/guardrails/skills/sdd-constitution/references/sdd-process.md:60`; `platforms/ci/README.md:17` gives
journeys as `J-NN[-slug].md`. The validators already accept both forms: `check_spec.py` reads the id from the start of
the file name (`ID_PREFIX`, line 384; rule `id-file`, line 1357), and `spec_trace.py` globs `NEED-*.md`, `J-*.md`,
`PROC-*.md` and `ENB-*.md`.

[FACT] The projects split between the two forms. Stratics (`dev-game-studio/stratics` 643b69888): all 129 FEAT files,
the 670 REQ files and the 64 journeys are named by the id alone; 177 decision and NEED files carry a slug (DTEC 86,
DGME 59, DPRO 20, NEED 12). review-loop: 4 DPRO decisions carry a slug. The kit: its one FEAT under `docs/spec/`,
`features/KIT-102-red-check-two-phase.md`.

## Scope

- `platforms/ci/validations/check_spec.py`: a new rule `id-file-name` in `RULES`. It fires only where `id-file`
  passes, that is when the file stem starts with the record's frontmatter `id` followed by `-` (a slug):
  `decisions/DGME-001-servidor-autoritativo.md` holding `id: DGME-001` reports `id-file-name: rename to DGME-001.md`.
  A stem whose id prefix disagrees with the frontmatter stays an `id-file` finding alone. A file with no `id` (a folder
  `README.md`, `NEED-nnn-data/` evidence) is not read by it. Journeys: the rule also reads the names of
  `journeys/J-*.md` (the glob the `need-link` rule uses, lines 687 to 692) and fails a stem that is not `J-` and digits
  alone, so `J-01-login.md` reports `rename to J-01.md`. The docstring lines 26, 32 and 60 name `PROC-nnn.md`,
  `ENB-nnn.md` and `TASK-nnn.md`.
- `platforms/ci/validations/spec_trace.py` lines 77 and 86: the docstrings name `PROC-nnn.md` and `ENB-nnn.md`.
- `platforms/ci/validations/test_check_spec.py`: class `IdFileNameTest`, and the line 375 docstring names
  `PROC-nnn.md`; `test_check_spec_tasks.py:130`: its docstring names `TASK-nnn.md`.

  `plugins/guardrails/skills/sdd-intake/SKILL.md:28`, `sdd-constitution/references/sdd-process.md:60`,

## Out of scope

- Renaming a project's records and the paths that cite them: Stratics, NEED-014 in `dev-game-studio/stratics`;
  review-loop, its 4 DPRO decisions. Each lands before the kit release that ships `id-file-name`, since local skill
  runs follow the newest release whatever a project's CI pin says.
- The autolink settings: one per prefix and repository, set by its admin after its rename (Stratics NEED-014).
- Journey ids: they stay `J-NN` (owner, 2026-11-17). Their files are already `J-NN.md` in Stratics.
- The records KIT-001 to KIT-101 in `docs/features/`: no validator reads them (KIT-101), and they keep their names.
- Reading: `spec_trace.py` keeps accepting a slugged name (`JOURNEY_FILE`, `PROCESS_FILE`), so a project with no
  `baseline.json` that baselines the rule still traces.

## Plan

### Tests

`IdFileNameTest` in `platforms/ci/validations/test_check_spec.py` writes a throwaway spec as `DecisionKindsTest` and
`NeedTest` do: one test per CA-1 to CA-5 (a slugged decision; the same decision by its id with a folder README and a
`NEED-nnn-data/` folder; a slugged journey; `--baseline-init` on a spec with no baseline, then a new slugged record; a
name whose id disagrees). CA-6 runs the seven modules whose fixtures change; CA-7 is the kit's own spec gate; CA-8 is
the grep.

### Risks

- A project with slugged records fails the spec check once it runs the release that ships the rule, and local skill
  runs follow the newest release (`~/.ai-kit` per `platforms/tools/refresh.sh:221`, the plugin per `stable`,
  `.github/CONTRIBUTING.md:51`). A project that keeps a `baseline.json` cannot baseline the new findings:
  `--baseline-init` refuses an existing file (`check_spec.py:1427-1431`), `--baseline-update` only lowers entries
  (`:1197-1207`), and the spec-tools action fails a PR that adds one (`platforms/ci/actions/spec-tools/action.yml:157`).
  For such a project, renaming first is the only path. [FACT] Stratics keeps `docs/spec/baseline.json` at
  643b69888, so its NEED-014 rename and review-loop's 4 renames merge before this release.
- A slugged name outside `docs/spec/` breaks only when the project renames; this change touches no project file.
  [FACT] Stratics at 643b69888: `git grep -c -F -f <its 177 slugged stems> 643b69888 -- . ':!game/legacy'` counts
  1,706 lines in 256 files, 1,274 of them in 131 files outside `docs/spec/`, and 1,120 of those lines are `"source"`
  fields in server content JSON and tests.
- The listing of a folder no longer tells what a record is about: the title stays in each record's frontmatter
  `title` and in the `spec.md` indexes.

## Decisions

- 2026-11-17 (owner chat): chose one form for every record, `<id>.md`, over a profile key choosing slug or id, because
  the owner asked for one standard and a key would double every skill line that names a record file. This reverses
  the `KIT-nnn-slug.md` naming that `docs/features/KIT-101-kit-own-flow.md:31` set for the kit's own FEATs.
- 2026-11-17 (owner chat): chose a new rule `id-file-name` over tightening `id-file`, so a project can baseline the
  rename apart from a file whose name and id disagree.
- 2026-11-17 (#381): chose `processes/README.md` over `needs/README.md` for the CA-2 folder README, because
  `check_spec.py` reads every top-level Markdown file in `needs/` as a NEED record (its docstring, #288), so a
  `needs/README.md` fails `frontmatter` before and after this change; `processes/` and `enablers/` are the folders
  whose `README.md` is no record (`NAMED_FILES`, #356).
- 2026-11-17 (#381): chose to read journeys by file name in the targets loop over adding `journeys/` to the
  frontmatter targets, because `check_spec.py` validates no journey frontmatter today and the rule needs only the
  name; any stem but `J-` and digits fails (`J-01_login`, `J-02-Login`: `rename to J-01.md`; `J-3-login`: `not
  J-NN.md`), as Scope says, not only the lowercase form `JOURNEY_FILE` reads (review of #384).
- 2026-11-17 (#384 review): widened CA-8 to any `<PREFIX>-nnn-<word>` name, because the first grep (`nnn-slug` forms)
  missed six lines that told projects a name the rule rejects: `security/references/vulnerability-process.md:8`
  (`PROC-nnn-no-vulnerabilities.md`), `spec-index-business.md:81` and `spec-index-game.md:91` (`ENB-001-billing.md`,
  `ENB-001-battle.md`), `platforms/ci/README.md:13` (`REQ-F-nnn-*`), `project-agents-godot-2d.md:81` and
  `project-agents-java-spring.md:13` (`DEC-nnn-*.md`). The pattern skips branch names (`feature/FEAT-nnn-name`) and
  links to the archived `docs/features/KIT-0nn-*.md` records, which keep their names.
