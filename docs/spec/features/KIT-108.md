# KIT-108 — A retired REQ needs no FEAT

## Problem and evidence

[FACT] `sdd-check` C20 retires the newer of two duplicate REQs (`duplicates.md` § Judge a candidate), but
`check_spec.py` rule `req-unlisted` fails every REQ that no FEAT lists and no open NEED lists, whatever its `status`
(the REQ loop in `check_spec.py`, "has no FEAT implementing it and no NEED listing it"). When the retired REQ's links
move to the kept one, a retired REQ that only open FEATs cited ends with `features: []` and fails; listing it in a NEED
only defers the failure until the NEED is delivered. dev-game-studio/stratics#4867 (DPRO-028 rule 4) keeps each
retired REQ listed in every open FEAT to satisfy the validator. `spec_trace.py similar` already skips retired REQs.
Source: issue #391, approved by the owner on 2026-11-18.

## Scope

- `platforms/ci/validations/check_spec.py`: the `req-unlisted` loop skips a REQ whose frontmatter `status` is
  `retired`, with and without `sdd.needs: false`. The `link-missing` check on the REQ's `features` stays.
- `platforms/ci/validations/test_check_spec.py`: three tests (CA-1 to CA-3).
- `plugins/guardrails/skills/sdd-check/references/duplicates.md`: C20 names the kept REQ in the History line and says
  which links move.
- `CHANGELOG.md`: one line citing `KIT-108`.

## Out of scope

- A `replaced_by` field on the REQ schema (the stricter alternative in #391): a schema change for every project. Prefer
  it if `sdd-check` finds a REQ retired by mistake within the next releases.
- Moving a project's own links (Stratics DPRO-028): a change in that repository after the release.

## Acceptance criteria

| CA-2 | the same REQ under `sdd.needs: false` | `check_spec.py` runs | no finding, exit 0 | `python3 platforms/tools/run_tests.py platforms/ci/validations/test_check_spec.py` |
| CA-3 | an `approved` REQ with `features: []` and no NEED | `check_spec.py` runs | it still fails with `has no FEAT implementing it and no NEED listing it` | `python3 platforms/tools/run_tests.py platforms/ci/validations/test_check_spec.py` |

## Plan

### Tests

Three tests in `NeedTest` of `test_check_spec.py`, on the throwaway spec the class builds; CA-3 is the falsifier. The
first two fail on `9ebf878` without the change and pass with it.

### Risks

- A REQ retired by mistake no longer shows up as unlisted, and no check catches it. `sdd-check` reads the History line
  of every retired REQ; if it finds one that hides a rule still needed, move to the `replaced_by` alternative.

## Decisions

- 2026-11-19 (issue #391): chose to skip every retired REQ over requiring a `replaced_by` field, because the field is
  a schema change for every project and a REQ retired as "no longer wanted" has no replacement.
