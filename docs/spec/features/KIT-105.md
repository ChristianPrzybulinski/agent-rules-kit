# KIT-105 — File closeout kit proposals directly as GitHub issues

## Problem and evidence

[FACT] The owner requested in Codex on 2026-11-18: "aplique iuma melhoria no KIT, para quando encerrarmos a sessao, na regra que temos pra propor uma melhoria, ja criar a issue no github diretamente."

[FACT] At base `b5e8306`, the global Session bullet asks before writing the proposal, and the session reference asks whether to do, defer, adjust or discard it without requiring an issue.

[DECISION] Type: platform; route: feat-only; size: S; priority: now; confirmed by: owner, 2026-11-18, the request above. The outcome is a persistent proposal and a confirmed issue link at closeout. A GitHub failure must leave an explicit unverified filing, never a false success. Scope is the existing proposal workflow; implementation of a future proposal remains separately approved.

## Scope

- `plugins/guardrails/AGENTS.md`: authorize filing the single closeout proposal directly, with its link, while preserving approval for implementation.
- `plugins/guardrails/skills/session/SKILL.md`: route review to the filing procedure.
- `plugins/guardrails/skills/session/references/kit-proposal.md`: search open and closed issues, reuse an open match, publish minimal safe evidence, confirm creation and report failures.
- `plugins/guardrails/evals/session-trigger-handoff/prompt.md`: keep the copied global trigger equal to the new bullet.
- `CHANGELOG.md`: record the behavior under Unreleased.
- This file: record the request, boundary, criteria and proof.

## Out of scope

- Implementing future proposals, release publication, changing credentials, or automatic kit edits.
- Changing the audit mode's approval policy or filing consumer-project discoveries as kit issues.

## Plan

### Tests

Read the full diff and exercise the new/duplicate/rejected/no-signal/private-evidence/failure decisions by inspection. Run the existing affected session evals and kit gates; do not create fake public issues for testing. The real tracking issue for this request verifies access and issue creation, not automatic behavior in a later session.

### Risks

The kit repository is public. Only minimal public-safe evidence may be filed, using an explicit repository and a literal body file. An uncertain write is checked before retrying. Filing authorizes no implementation or release; audit mode retains its own approval rule. Future sessions receive the change through the normal kit release/install process.

## Decisions

- 2026-11-18: chose direct issue capture over chat-only proposals (not persistent) and per-issue confirmation (the interruption the owner asked to remove). Private disclosure or implicit implementation approval would invalidate the choice; both are explicitly excluded.
- 2026-11-18: preserve the observed-signal threshold, one-proposal limit and implementation approval; change only capture at closeout.
