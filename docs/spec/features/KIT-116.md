# KIT-116 — A row that adds an enabler consumer lists both ENB files

## Problem and evidence

[FACT] Stratics' gate runs `platform/tools/enablers/enablers.py drift`. It fails a PR whose code starts using another
ENB's contract until the consumer's Required contracts and the provider's Consumers say so. On 2026-11-21 it failed
two PRs. Neither task row listed the ENB files in Files, so each PR spent a fix round on a scope widening done by hand:

- stratics-client#5259 (issue #5214, FEAT-091 T15/T20/T21): `ENB-029 hall_of_fame Consumers: missing ENB-021`.
- stratics-client#5266 (issue #4215, FEAT-025 T25/T27): `ENB-005 content.moves Consumers: missing ENB-022`.

Both lines are from each PR's gate record. Neither `sdd-tasks` nor `row-checks.md` asked a row to list the ENB files
it changes. `row_checks.py` did not read `docs/spec/enablers/`.

## Scope

- `platforms/ci/validations/row_checks.py`: rule `n` (WARN, promoted to FAIL by `--strict`) reads every ENB that is
  not retired under `<spec>/enablers/`: its Code globs, its Provided contracts with their Consumers ENB ids, and its
  Required contracts.
  - A row's consumers are the ENBs whose Code its Files reach.
  - Its contracts are the ids other ENBs provide that its Task names: backticked, or bare when the id holds a `.`,
    `_` or `-`.
  - When a contract is missing from the consumer's Required contracts, the row needs the consumer's file. When the
    consumer is missing from the provider's Consumers, it needs the provider's file.
  - A Files entry that covers the ENB file, such as `docs/spec/enablers/**`, satisfies the rule.
  - A row whose Files also reach the provider's Code builds that side of the contract and is skipped.
- `platforms/ci/validations/test_row_checks_enablers.py`: the tests.
- `plugins/guardrails/skills/sdd-tasks/SKILL.md` § 2 and `references/row-checks.md` (Scope and the rule table): the
  rule in prose. The `spec` label comes from the project's own `protected_paths` entry on the spec folder, so the
  kit holds no Stratics name.
- `CHANGELOG.md`; `docs/spec/spec.md`: the index row.

## Out of scope

- A consumer the Task does not name, such as the #5266 case: a "tutor picker" reads `content.moves`, a contract
  the row never names. Only the prose rule and the planner cover it; Stratics' drift check stays the backstop.
- A contract change that leaves its consumers alone (a version, a path), and a row that builds the provider and a
  consumer at once (for example FEAT-025 T27, Files on both `client/features/quest/**` and `client/features/world/**`).
  Covering them by name or path flagged 28 Stratics rows, mostly wide rows naming several contracts.
- Stratics' own `enablers.py`; its gate config needs no change.

## Plan

### Tests

`test_row_checks_enablers.py` builds three ENBs in the fixture repository. Run against `row_checks.py` from `main`,
4 of its 9 tests fail (the ones that expect a finding), and all pass with rule `n`. CA-5 measures the rule on the
real Stratics tables.

### Risks

- A false positive: a wide row that reaches several ENBs and names a contract only one of them uses. The finding is
  a WARN that names the file and the contract, and the fix (one more Files entry) is cheap. The first version flagged
  28 Stratics rows; skipping a row that also reaches the provider's Code brought that to 8.
- A missed consumer: a contract the Task does not name. The prose rule asks the planner for it, and the project's
  drift check still catches it at the PR.
- If the warning is ignored and a drift fix round still follows a planned row, run the row check with `--strict` (the
  project's `row_check`).

## Decisions

- 2026-11-21 (#436): a WARN with `--strict`, like rules `l` and `m`, over a FAIL. The gate's
  `row_checks.py --changed` would otherwise fail every edit of a FEAT that holds one of the 8 open rows.
- 2026-11-21 (#436): name or backtick matching of contract ids over a path-only rule. Every row of a client feature
  reaches some ENB's Code, but only the Task says which contract the code will use.
