# tools/ — kit lifecycle on the machine

| File | Scope | When to use |
|---|---|---|
| `bootstrap.sh` | clones the kit at the newest release tag, connects agent plugins, installs launchd, then runs doctor | first setup on a machine |
| `review_checks.py` | the mechanical steps of a delivery review (KIT-069): `red` runs the PR's added or changed test files on base and head and classifies each failure (assertion or new-symbol Red; a test-only PR exempt; runtime, all-pass and data-only Reds flagged), `scope` checks the Files cell and `## Files widened`, `proof` checks the PR body's `## Red`, `proof` block and executor line and re-runs allowlisted proof lines, `feat-proofs` re-runs every Proof cell of a FEAT, both checking paths first and failing on a stack's output pattern at exit 0, `dod` matches the project `REVIEW.md` grep lines and dropped assertions (a rename out of the test globs drops them, and with `--gates` so does one out of every `red` glob; a rename inside both keeps them, KIT-079); exit 1 on a finding, 3 on a flag, 2 on a usage error | skill `review` § 1 and `sdd-review` § 2, on a clean checkout |
| `refresh.sh` | checks the clone out at the newest release tag on `origin/main` (#271), moves the Codex marketplace to that ref (and adds the kit plugins again) and updates Codex/Claude marketplaces and plugins; when the checkout changed `refresh.sh`, `codex-bin.sh` or `kit-release.sh` it hands over once to the new script (KIT-046); reinstalls a Claude plugin whose cache differs from the kit (KIT-013); logs a `skip:` line when the `claude` or `codex` CLI is missing (KIT-022); runs `session_audit.py --if-older-days 7` unless `AI_KIT_SESSION_AUDIT=0` (KIT-056) | scheduled refresh or manual update |
| `doctor.sh` | fails when the clone, the Codex marketplace ref or Devin's plugin ref is not at the newest release tag (#271), moving the Codex ref itself; verifies plugins/symlinks, warns on a stale Claude plugin cache, merges Devin import policy, cleans legacy state and checks budgets; `AI_KIT_USER_RULES=1` restores user-level rule symlinks (default 0: repos carry `.claude/rules`); warns about each project Claude Code records an `@ai-kit` install for that vendors kit copies but still loads `guardrails@ai-kit` beside them, and about each pinned checkout whose main checkout root `~/.claude.json` does not mark `hasTrustDialogAccepted` (KIT-072) | diagnose setup or after refresh |
| `codex-bin.sh` | finds the Codex CLI for bootstrap, refresh and doctor, which source it: `$CODEX_BIN`, `codex` on `PATH`, ChatGPT.app or Codex.app, `~/.cache/codex-runtimes`; run directly it prints the CLI it found (KIT-023) | check which Codex CLI the kit uses |
| `kit-release.sh` | the release the user install follows, for bootstrap, refresh and doctor, which source it: `kit_release_tag` (the newest `vX.Y.Z` on `origin/main`), `codex_kit_ref` (the `ai-kit` ref in Codex's `config.toml`) and the repository name; run directly it prints the tag (#271) | check which release the machine follows |
| `smoke.sh` | runs bootstrap and doctor against isolated throwaway homes; `--main` stops after the main path (bootstrap, the Codex `AGENTS.md` link and its repoints, a clean doctor run), which `platforms/ci/validations/test_smoke.py` runs as an integration test, while the whole script is a functional test in `ci-full.yml` (KIT-077) | after lifecycle changes; in CI |
| `vendor.sh` | installs pinned third-party skills; `--check` verifies the lock | update or verify vendored skills |
| `complexity.py` | advisory complexity of changed functions: Java CRAP from a JaCoCo XML the build wrote, GDScript CC from `gdradon cc` joined by function name, or CRAP when `--gd-coverage JSON` (a `gd_coverage.py --json` report, repeatable) holds the function, joined by repository-relative path and `func` line; `[FILE...]` measures whole files; exit 0, `--threshold N` exits 1 at N and 2 on a missing or unreadable report or gdradon (KIT-031, KIT-034) | before a PR or a completion verdict that touches `.java` or `.gd` |
| `gd_duplicates.py` | advisory structural duplicates of changed GDScript functions: gdtoolkit parse tree, names and numbers normalised, strings kept, Jaccard of subtree fingerprints, pairs at 0.82 or more against the whole tree; `[FILE...]` or `--all` widen it; fingerprints cached by file content under `$XDG_CACHE_HOME/ai-kit/gd-duplicates`; exit 0, `--threshold S` exits 1 at S and 2 without gdtoolkit (KIT-033) | before a PR that touches `.gd` |
| `gd_coverage.py` | advisory line and branch coverage of GDScript functions under gdUnit4: `git archive` of the Godot project into a temporary folder (LFS pointers filled from the local store), probes inserted with gdtoolkit without changing a line number, one headless import and the gdUnit4 suite under `nice -n 10` with `HOME` in the folder, killed with its child processes after `--timeout S` (default 1800); `--exclude PATH` leaves a script a test copies out of the project without probes; `--ignore SUITE`, repeatable, goes to gdUnit4 as `-i` (a suite name, a path or `suite:test`) to leave out tests that inspect the project's own autoloads or dependencies and so see the probes; `HOME` moves, so a test that starts `python3` and imports user site-packages needs the caller's `PYTHONUSERBASE`; one `path:line function lines C/T branches C/T` line per function, `--json FILE` per statement and outcome; `[FILE...]` or `--base REF` narrow it; exit 0, and 2 when the run does not count (timeout, exit other than 0 or 101, no test case, no counters) or godot, gdUnit4 or gdtoolkit is missing (KIT-034) | before a PR that touches `.gd` game rules |
| `gd_mutation.py` | advisory mutation testing of GDScript functions under gdUnit4 with PIT 1.30.0's default operators (boundary, negated conditions, math, increments, negation, void calls and typed returns), placed from the gdtoolkit tree as one edit that keeps every line number and parses again, never a value the return type cannot hold; `git archive` copy imported once, one APFS clone per worker (`--workers N`, an upper bound: every Godot run starts only while fewer than 2 gate runs of the review loop hold the host, and one beside another of ours only while the load is below the core count), the suites under `--tests` that name the file's `class_name` or `res://` path, an unmutated baseline per selection and a timeout of 10 × its time plus `--timeout-constant S` (default 30, PIT's shape); statuses killed, survived, timed out, invalid, error, "not run" when writing or running a mutant raises, "no tests" and, with `--coverage` (`gd_coverage.py --json`), "no coverage" without a run; one survivor per line, `--json FILE` per mutant; `--cache FILE` (default `$XDG_CACHE_HOME/ai-kit/gd-mutation/cache.json`) keeps killed, survived and invalid (a timed-out mutant runs again) under a hash of the function's text and its selected test files, so a second run with nothing changed starts no Godot, and `--no-cache` runs every mutant; `[FILE...]` or `--base REF` narrow it; exit 0, and 2 when godot, gdUnit4 or gdtoolkit is missing, the import or a baseline fails or a mutant is not run (KIT-035) | before a PR that touches `.gd` game rules |
| `session_audit.py` | cross-session audit pre-filter, standard library only and no model tokens: reads the Claude Code transcripts and Codex rollouts that grew since the last run (byte offsets in its state) and writes one redacted extract (owner corrections, `Kit [PROPOSAL]` blocks, tool errors in 2 or more sessions, memory citations, guard blocks by target) with mode 0600 to `${XDG_STATE_HOME:-~/.local/state}/ai-kit/session-audit/`; `exclude.txt` (id prefix, Claude title or Codex thread name) and personal-topic keywords, checked from a session's first line, skip whole sessions and remove them from the kept extracts, rebuilt from an `index-*.json`; prints counts only; `--if-older-days N` runs only when the last run is N or more days old (KIT-056) | weekly from `refresh.sh`; before skill `session` in `audit` mode |
| `skill_usage.py` | skill loads per runtime, standard library only and no model tokens: for each kit skill (`--all` for every name, `--skill` for some), the Claude Code sessions that called it with a kit-prefixed Skill call or command or read its `SKILL.md` (a bare-name call reported apart, since `review` is also a bundled skill; subagent and workflow transcripts count for their session) and the Codex rollouts whose tool calls name its `SKILL.md`, among transcripts modified in the last `--days` (30); `--project` filters both runtimes, `--listings` reports the Claude skill listings (size, entries without a description, kit skills listed twice); a table, or `--json` (KIT-071) | before and after a change meant to raise skill use; `--rules` reports rule loads instead (KIT-070): per kit rule, the loads and sessions the plugin's InstructionsLoaded hook recorded in `~/.claude/plugins/data/guardrails-ai-kit/instructions-loaded.jsonl` (`--rule-log` for another file), and the Codex sessions whose tool calls opened a kit skill reference |
| `bump_version.py` | `X.Y.Z [--date YYYY-MM-DD]` writes `VERSION`, every manifest `"version"` and the CHANGELOG heading; refuses a version not above `VERSION`, a dirty tree or an empty `[Unreleased]`; `--notes X.Y.Z` prints the release notes as `release.yml` cuts them (KIT-019) | first step of a kit release (`.github/CONTRIBUTING.md` § Versioning) |
| `check.sh` | validates the kit and Claude manifests; `--spec <dir>` validates project specs | after any kit change; in CI |
| `run_tests.py` | the kit's test runner (KIT-077): selects the `platforms/ci/validations` tests by the `LAYER` each module or class sets (`unit`, `contract`, `integration`, `functional`, `performance`) and runs them in parallel worker processes; `--changed-from REF` keeps only the integration classes whose `COVERS` globs or own module the change touches (a change to code no `COVERS` names runs the whole layer), `--shard I/N` splits a layer over CI jobs, `FILE ...` runs those modules whole, each on its own so one that cannot import is one error (the red job's base run, KIT-079); unittest's summary lines, the skips by reason, `--durations N` and `--json FILE`; exit 1 on a failure, 2 on an untagged class or a usage error | the TDD loop (`--layer unit,contract`, or the modules you changed); the jobs of `ci.yml`, `ci-full.yml` and `performance.yml` |
| `ci_red.py` | the `red` job of `ci.yml` (KIT-077): `review_checks.py red` on a pull request's merge commit (base `HEAD^1`, head `HEAD^2`) with `run_tests.py` on the PR's test modules, the output in the job summary; OK, EXEMPT and a FLAG pass (a FLAG with a warning), NONE passes with a notice only when the PR body's `## Red` opens with `Exception`; a push or dispatch has nothing to compare | in CI only |
| `release_guard.py` | the first step of `release.yml` (KIT-077): reads the `ci-full.yml` runs of the tagged commit through `gh api`; a green run passes, and while none exists yet or one is queued or in progress it waits (`--wait` minutes, `--poll` seconds); a completed run that is not green, or the timeout, fails the job, so no release is published; it never deletes or moves the tag (ruleset `protect-release-tags`): re-run `release.yml` once `ci-full` is green; exit 2 when `gh` fails | in CI only |
| `gen_index.py` | generates every `plugins/*/INDEX.md` from the plugin's `skills/*/SKILL.md` frontmatter and its `AGENTS.md`, `rules/`, `agents/`, `templates/`, `evals/` and `hooks/`; `--check` lists stale files and exits 1 (KIT-040) | after adding, removing or renaming a plugin entry or changing a skill `description`; `check.sh` runs the check |
| `sync-project.sh` | copies spec validation files (`check_spec.py`, `row_checks.py` and the `pr_gates.py` it imports, `spec_trace.py`, the schemas; the journey schema with journeys) into a project that has `docs/spec` and generates `CLAUDE.md` (imports `AGENTS.md`), `.claude/settings.json` (kit marketplace and `guardrails@ai-kit`; profile `godot|java|docs|python`: `--profile`, else the list `.claude/skills/KIT_MANIFEST.json` records, else inferred, and the run prints which source won; a comma list such as `docs,godot:client,java:server` syncs the union for a monorepo, `:<dir>` scoping that profile's rule globs) and `.claude/rules/guardrails-<rule>.md` (the profile's path rules per `sync-profiles.txt`, marked generated); `docs/spec/spec.md` `sdd.rule_paths` (rule → folders) scopes a rule's globs and wins over the profile folders, and each folder its rules start in gets a generated path-rule block in its `AGENTS.md` through `sync_agents_md.py` (KIT-067); `--check` compares all of them and scans the repo's `*.md` for obsolete kit paths; `--workflow <file>` names the CI file that runs `check_spec.py` (any name is accepted if it does); `--vendor-skills` copies the profile's skills into `.claude/skills/` with a hashed `KIT_MANIFEST.json` and pins the kit (KIT-072) through `sync_pinned_plugin.py`: the kit hooks go to `.claude/ai-kit/hooks/` and run from `.claude/settings.json` `hooks`, the agents and the other skills to `.claude/skills/guardrails-pinned/`, then `guardrails@ai-kit` is set to `false`; `--check` also reads `settings.local.json` and, with `AI_KIT_CLAUDE_PROBE=1`, the plugins Claude Code lists for the repository; each profile folder gets a generated `kit.just` (`sync_just.py`), a godot profile the keyed-CSV merge driver in `.github/merge-drivers/` (the one-time `git config` step is printed, never run), and `sdd.doc_structure.enabled` the opt-in `check_docs_structure.py` in `.github/spec-lint/` (KIT-074) | initialize or refresh a project; in the project's CI |
| `sync_pinned_plugin.py` | `preflight|write|settings|rewrite|remove|pin|check`: a vendored project's pin of `plugins/guardrails/`: the kit hooks as scripts in `.claude/ai-kit/hooks/` with the settings fragment that runs them, every kit tool or template the kit text calls as `~/.ai-kit/platforms/<path>` or `$HOME/.ai-kit/platforms/<path>` (with the modules it imports) in `.claude/ai-kit/platforms/`, which `rewrite` points the vendored skill copies and rules at, and `.claude/skills/guardrails-pinned/`, a skills-directory plugin with the agents, templates and every skill not copied as a plain skill, its agent preloads renamed to the names that resolve in the project; `settings` merges the hooks into `.claude/settings.json` beside the project's own, drops retired `@ai-kit` keys and turns `guardrails@ai-kit` off once the pin is written; `preflight` refuses a symbolic link or an unmarked folder at either path (exit 1) and settings whose `enabledPlugins` or `hooks` it cannot merge into (exit 2); `pin` prints `KIT_COMMIT`, the hashes and `copies` (the hash of each file `sync-project.sh` `pin_sources` lists on stdin, one `<source><TAB><repo path>` line each so a path may hold a space (KIT-079): every `kit_files()` entry, the keyed-CSV merge driver and each generated `kit.just`/`kit-<profile>.just`, KIT-074) for `KIT_MANIFEST.json`; `check` exits 1 on a changed pinned file or copy, a `kit_files()` entry the pin lacks, settings without the kit hooks or with `guardrails@ai-kit` on (`settings.local.json` included), or, with `AI_KIT_CLAUDE_PROBE=1`, `claude plugin list` showing the head loaded or no pinned copy loaded (KIT-072) | called by `sync-project.sh` |
| `sync_agents_md.py` | `preflight|write|check <repo> <kit-version> <rules-dir>`: the path-rule block in each folder's `AGENTS.md`, built from the rules `sync-project.sh` rendered: one block per folder a rule's globs start in, for runtimes that load no rule by path; `write` replaces, appends, creates or removes it, `check` exits 1 on a missing, diverging or stale block, `preflight` refuses a symbolic link, a folder reached through a symbolic link or broken markers before any write; the text around the block and its dominant line ending are kept, and nested checkouts keep their own blocks (KIT-067) | called by `sync-project.sh` |
| `sync_just.py` | `preflight|write|check|list <repo> <kit-version> <profile-list>`: the generated `kit.just` in each profile folder, from `platforms/kits/just/<profile>.just`; a folder with several profiles gets `kit-<profile>.just` modules and a `kit.just` that runs each one's `fmt`, `lint`, `test` and `verify`; a folder without a justfile gets a starter one that imports `kit.just` (the project's own afterwards); `preflight` refuses an unmarked file at a module path, a folder reached through a symbolic link and a `justfile` that is a symbolic link or not a regular file, `write` removes marked modules no profile needs, `check` exits 1 on a missing, diverging or stale module or a justfile that does not import `kit.just`, `list` prints the module paths for the pin (KIT-074) | called by `sync-project.sh` |
| `sync-profiles.txt` | one line per `guardrails` skill and rule: the profiles (`godot java python docs`, or `-` for none) that receive its vendored copy or its `.claude/rules/` file; `sync-project.sh` reads it and `check_kit.py` requires exactly one line for each (KIT-047) | after adding, removing or renaming a `guardrails` skill or rule |
