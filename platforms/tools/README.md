# tools/ — kit lifecycle on the machine

| File | Scope | When to use |
|---|---|---|
| `bootstrap.sh` | clones the kit at the newest release tag, connects agent plugins (the Claude Code and Codex marketplaces at the `stable` branch, KIT-081), installs launchd, then runs doctor | first setup on a machine |
| `review_checks.py` | the mechanical steps of a delivery review (KIT-069): `red` runs the PR's added or changed test files on base and head and classifies each failure (assertion or new-symbol Red; a test-only PR exempt; runtime, all-pass and data-only Reds flagged; in two phases with `--plan OUT.json`, the selection and the command as JSON with nothing run, and `--sides-from DIR`, the verdict from a runner's `base/` and `head/` exit code, output and JUnit reports through the same judge, KIT-102), `scope` checks the Files cell and `## Files widened`, `proof` checks the PR body's `## Red`, `proof` block and executor line and re-runs allowlisted proof lines, `feat-proofs` re-runs every Proof cell of a FEAT, both checking paths first and failing on a stack's output pattern at exit 0, `dod` matches the project `REVIEW.md` grep lines and dropped assertions (a rename out of the test globs drops them, and with `--gates` so does one out of every `red` glob; a rename inside both keeps them, KIT-079); exit 1 on a finding, 3 on a flag, 2 on a usage error | skill `review` § 1 and `sdd-review` § 2, on a clean checkout |
| `refresh.sh` | checks the clone out at the newest release tag on `origin/main` (#271); moves a Codex marketplace off the `stable` branch to it once (and adds the kit plugins again), and a Claude Code one once too: it copies each kit plugin's data folder to `${XDG_STATE_HOME:-~/.local/state}/ai-kit/plugin-data-backup/<UTC time>/`, removes the user-scope marketplace, adds it at `#stable`, installs the kit plugins at user scope and copies the backup back (a newer file stays; a `.jsonl` keeps the backup's lines first), keeps the backup and on a failure names the commands left (KIT-081); otherwise updates the Codex/Claude marketplaces and plugins; when the checkout changed `refresh.sh`, `codex-bin.sh` or `kit-release.sh` it hands over once to the new script (KIT-046); reinstalls a Claude plugin whose cache differs from the kit (KIT-013); logs a `skip:` line when the `claude` or `codex` CLI is missing (KIT-022); runs `session_audit.py --if-older-days 7` unless `AI_KIT_SESSION_AUDIT=0` (KIT-056) | scheduled refresh or manual update |
| `doctor.sh` | fails when the clone is not at the newest release tag (#271), or the Claude Code marketplace ref, the Codex marketplace ref or Devin's plugin ref is not the `stable` branch (KIT-081), moving the Codex ref itself and naming `refresh.sh` for Claude Code; verifies plugins/symlinks, warns on a stale Claude plugin cache, merges Devin import policy, cleans legacy state and checks budgets; `AI_KIT_USER_RULES=1` restores user-level rule symlinks (default 0: in a synced repository the guardrails plugin's hook gives the rules, KIT-081 stage 3); warns about each checkout Claude Code records an `@ai-kit` install for that still holds the vendored kit state KIT-081 stage 2b removed, naming `sync-project.sh <repo>`, which removes it | diagnose setup or after refresh |
| `codex-bin.sh` | finds the Codex CLI for bootstrap, refresh and doctor, which source it: `$CODEX_BIN`, `codex` on `PATH`, ChatGPT.app or Codex.app, `~/.cache/codex-runtimes`; run directly it prints the CLI it found (KIT-023) | check which Codex CLI the kit uses |
| `kit-release.sh` | the release and the branch the user install follows, for bootstrap, refresh and doctor, which source it: `kit_release_tag` (the newest `vX.Y.Z` on `origin/main`), `KIT_STABLE_BRANCH` (`stable`, which `release.yml` moves to each release, KIT-081), `codex_kit_ref` (the `ai-kit` ref in Codex's `config.toml`), `claude_kit_ref` (the `ai-kit` ref in Claude Code's `known_marketplaces.json`, under `CLAUDE_CODE_PLUGIN_CACHE_DIR`, else `${CLAUDE_CONFIG_DIR:-~/.claude}/plugins`) and the repository name; run directly it prints the tag (#271) | check which release the machine follows |
| `smoke.sh` | runs bootstrap and doctor against isolated throwaway homes; `--main` stops after the main path (bootstrap, the Codex `AGENTS.md` link and its repoints, a clean doctor run), which `platforms/ci/validations/test_smoke.py` runs as an integration test, while the whole script is a functional test in `ci-full.yml` (KIT-077) | after lifecycle changes; in CI |
| `complexity.py` | advisory complexity of changed functions: Java CRAP from a JaCoCo XML the build wrote, GDScript CC from `gdradon cc` joined by function name, or CRAP when `--gd-coverage JSON` (a `gd_coverage.py --json` report, repeatable) holds the function, joined by repository-relative path and `func` line; `[FILE...]` measures whole files; exit 0, `--threshold N` exits 1 at N and 2 on a missing or unreadable report or gdradon (KIT-031, KIT-034) | before a PR or a completion verdict that touches `.java` or `.gd` |
| `gd_duplicates.py` | advisory structural duplicates of changed GDScript functions: gdtoolkit parse tree, names and numbers normalised, strings kept, Jaccard of subtree fingerprints, pairs at 0.82 or more against the whole tree; `[FILE...]` or `--all` widen it; fingerprints cached by file content under `$XDG_CACHE_HOME/ai-kit/gd-duplicates`; exit 0, `--threshold S` exits 1 at S and 2 without gdtoolkit (KIT-033) | before a PR that touches `.gd` |
| `gd_coverage.py` | advisory line and branch coverage of GDScript functions under gdUnit4: `git archive` of the Godot project into a temporary folder (LFS pointers filled from the local store), probes inserted with gdtoolkit without changing a line number, one headless import and the gdUnit4 suite under `nice -n 10` with `HOME` in the folder, killed with its child processes after `--timeout S` (default 1800); `--exclude PATH` leaves a script a test copies out of the project without probes; `--ignore SUITE`, repeatable, goes to gdUnit4 as `-i` (a suite name, a path or `suite:test`) to leave out tests that inspect the project's own autoloads or dependencies and so see the probes; `HOME` moves, so a test that starts `python3` and imports user site-packages needs the caller's `PYTHONUSERBASE`; one `path:line function lines C/T branches C/T` line per function, `--json FILE` per statement and outcome; `[FILE...]` or `--base REF` narrow it; exit 0, and 2 when the run does not count (timeout, exit other than 0 or 101, no test case, no counters) or godot, gdUnit4 or gdtoolkit is missing (KIT-034) | before a PR that touches `.gd` game rules |
| `gd_mutation.py` | advisory mutation testing of GDScript functions under gdUnit4 with PIT 1.30.0's default operators (boundary, negated conditions, math, increments, negation, void calls and typed returns), placed from the gdtoolkit tree as one edit that keeps every line number and parses again, never a value the return type cannot hold; `git archive` copy imported once, one APFS clone per worker (`--workers N`, an upper bound: every Godot run starts only while fewer than 2 gate runs of the review loop hold the host, and one beside another of ours only while the load is below the core count), the suites under `--tests` that name the file's `class_name` or `res://` path, an unmutated baseline per selection and a timeout of 10 × its time plus `--timeout-constant S` (default 30, PIT's shape); statuses killed, survived, timed out, invalid, error, "not run" when writing or running a mutant raises, "no tests" and, with `--coverage` (`gd_coverage.py --json`), "no coverage" without a run; one survivor per line, `--json FILE` per mutant; `--cache FILE` (default `$XDG_CACHE_HOME/ai-kit/gd-mutation/cache.json`) keeps killed, survived and invalid (a timed-out mutant runs again) under a hash of the function's text and its selected test files, so a second run with nothing changed starts no Godot, and `--no-cache` runs every mutant; `[FILE...]` or `--base REF` narrow it; exit 0, and 2 when godot, gdUnit4 or gdtoolkit is missing, the import or a baseline fails or a mutant is not run (KIT-035) | before a PR that touches `.gd` game rules |
| `session_audit.py` | cross-session audit pre-filter, standard library only and no model tokens: reads the Claude Code transcripts and Codex rollouts that grew since the last run (byte offsets in its state) and writes one redacted extract (owner corrections, `Kit [PROPOSAL]` blocks, tool errors in 2 or more sessions, memory citations, guard blocks by target) with mode 0600 to `${XDG_STATE_HOME:-~/.local/state}/ai-kit/session-audit/`; `exclude.txt` (id prefix, Claude title or Codex thread name) and personal-topic keywords, checked from a session's first line, skip whole sessions and remove them from the kept extracts, rebuilt from an `index-*.json`; prints counts only; `--if-older-days N` runs only when the last run is N or more days old (KIT-056) | weekly from `refresh.sh`; before skill `session` in `audit` mode |
| `skill_usage.py` | skill loads per runtime, standard library only and no model tokens: for each kit skill (`--all` for every name, `--skill` for some), the Claude Code sessions that called it with a kit-prefixed Skill call or command or read its `SKILL.md` (a bare-name call reported apart, since `review` is also a bundled skill; subagent and workflow transcripts count for their session) and the Codex rollouts whose tool calls name its `SKILL.md`, among transcripts modified in the last `--days` (30); `--project` filters both runtimes, `--listings` reports the Claude skill listings (size, entries without a description, kit skills listed twice); a table, or `--json` (KIT-071) | before and after a change meant to raise skill use; `--rules` reports rule loads instead (KIT-070): per kit rule, the loads and sessions the plugin's InstructionsLoaded hook recorded in `~/.claude/plugins/data/guardrails-ai-kit/instructions-loaded.jsonl` (`--rule-log` for another file), and the Codex sessions whose tool calls opened a kit skill reference |
| `bump_version.py` | `X.Y.Z [--date YYYY-MM-DD]` writes `VERSION`, every manifest `"version"` and the CHANGELOG heading; refuses a version not above `VERSION`, a dirty tree or an empty `[Unreleased]`; `--notes X.Y.Z` prints the release notes as `release.yml` cuts them (KIT-019) | first step of a kit release (`.github/CONTRIBUTING.md` § Versioning) |
| `check.sh` | validates the kit and Claude manifests; `--spec <dir>` validates project specs | after any kit change; in CI |
| `run_tests.py` | the kit's test runner (KIT-077): selects the `platforms/ci/validations` tests by the `LAYER` each module or class sets (`unit`, `contract`, `integration`, `functional`, `performance`) and runs them in parallel worker processes; `--changed-from REF` keeps only the integration classes whose `COVERS` globs or own module the change touches (a change to code no `COVERS` names runs the whole layer), `--shard I/N` splits a layer over CI jobs, `FILE ...` runs those modules whole, each on its own so one that cannot import is one error (the red job's base run, KIT-079); unittest's summary lines, the skips by reason, `--durations N` and `--json FILE`; exit 1 on a failure, 2 on an untagged class or a usage error | the TDD loop (`--layer unit,contract`, or the modules you changed); the jobs of `ci.yml`, `ci-full.yml` and `performance.yml` |
| `ci_red.py` | the `red` job of `ci.yml` (KIT-077): `review_checks.py red` on a pull request's merge commit (base `HEAD^1`, head `HEAD^2`) with `run_tests.py` on the PR's test modules, the output in the job summary; OK, EXEMPT and a FLAG pass (a FLAG with a warning), NONE passes with a notice only when the PR body's `## Red` opens with `Exception`; a push or dispatch has nothing to compare | in CI only |
| `release_guard.py` | the first step of `release.yml` (KIT-077): reads the `ci-full.yml` runs of the tagged commit through `gh api`; a green run passes, and while none exists yet or one is queued or in progress it waits (`--wait` minutes, `--poll` seconds); a completed run that is not green, or the timeout, fails the job, so no release is published; it never deletes or moves the tag (ruleset `protect-release-tags`): re-run `release.yml` once `ci-full` is green; exit 2 when `gh` fails | in CI only |
| `gen_index.py` | generates every `plugins/*/INDEX.md` from the plugin's `skills/*/SKILL.md` frontmatter and its `AGENTS.md`, `rules/`, `agents/`, `templates/`, `evals/` and `hooks/`; `--check` lists stale files and exits 1 (KIT-040) | after adding, removing or renaming a plugin entry or changing a skill `description`; `check.sh` runs the check |
| `sync-project.sh` | writes `.github/workflows/spec-lint.yml` into a project that has `docs/spec` and whose CI runs no spec tools, the spec-tools action pinned to the kit commit it runs from, and removes the `.github/spec-lint/` copy an older sync generated (KIT-081 stage 1, `sync_spec_tools.py`); generates `CLAUDE.md` (imports `AGENTS.md`; its marker records the kit version, and since KIT-087 P4 no profile list), `.claude/settings.json` (kit marketplace at `"ref": "stable"`, KIT-081, and `guardrails@ai-kit`; profile `godot|java|docs|python`: the `stacks` of the project's `.ai-kit.yaml` when it sets them (KIT-087 P2a; `--profile` must then name the same list, and a profile the resolver refuses stops the run with exit 2), else `--profile`, else (a vendored repository's migration) the one `.claude/skills/KIT_MANIFEST.json` records, else inferred, and the run prints which source won and warns when `stacks` are not set; a comma list such as `docs,godot:client,java:server` syncs the union for a monorepo, `:<dir>` scoping that profile's rule globs in the `AGENTS.md` blocks) and no `.claude/rules` copy since KIT-081 stage 3 (the profile's `stacks` select the rules the guardrails plugin's hook gives, per `plugins/guardrails/hooks/sync-profiles.txt`; install removes the kit-marked copies older syncs wrote through `sync_rules.py`, keeping the project's own rules, and `--check` names each copy left); the profile's `sdd.rule_paths` (rule → folders) scopes a rule's globs and wins over the profile folders, and each folder its rules start in gets a generated path-rule block in its `AGENTS.md` through `sync_agents_md.py` (KIT-067), which stays for Codex; `--check` compares all of them and scans the repo's `*.md` for obsolete kit paths; `--workflow <file>` names the CI file that runs the spec tools (the spec-tools action, or `check_spec.py` from `$AI_KIT_DIR`), which install writes from the template when it is missing; `--migrate-profile` exits 2 (removed in KIT-087 P4); `--vendor-skills` exits 2: the vendored mode that pinned the kit (KIT-072) was removed in KIT-081 stage 2b, and install migrates a repository that still holds its state through `sync_unvendor.py` (only kit-marked folders and the kit's settings entries go), which `--check` reports; no `justfile` is written or required (KIT-085: skill `sdd-implement` runs `just -f ~/.ai-kit/platforms/kits/just/<stack>.just -d <folder> <recipe>`), and a godot profile gets the one-time `git config` step that runs the installed kit's keyed-CSV merge driver (printed, never run); install removes the starter `justfile` (recognized by its whole text) and the kit-marked `kit.just`, `kit-<profile>.just` and `.github/merge-drivers/keyed_csv_merge.py` older syncs wrote, keeping a justfile with the project's own content and unmarked files (`sync_just.py`), and `--check` fails on each left, on a justfile line still importing the removed `kit.just` and on a git config that still runs the removed driver | initialize or refresh a project; in the project's CI |
| `sync_unvendor.py` | `remove|check <repo>`: the state the retired vendored mode (`--vendor-skills`, KIT-072) left in a project: `.claude/skills/KIT_MANIFEST.json`, each `.claude/skills/<name>/` (the plain copies and `guardrails-pinned/`) and `.claude/ai-kit/` that carries the generated `.agent-rules-kit` marker, and in `.claude/settings.json` the hook handlers that run `.claude/ai-kit/hooks/` and the `guardrails-pinned@skills-dir` key; `remove` deletes that state with one `sync: removed` line each and keeps the project's own hooks and keys, never reading, replacing or deleting an unmarked folder or a symbolic link (a `sync: kept` line names one the manifest or the pin expected); `check` prints one line per leftover and the sync that removes it and exits 1; `doctor.sh` imports its detection (KIT-081 stage 2b) | called by `sync-project.sh` and `doctor.sh` |
| `sync_spec_tools.py` | `remove|check|workflow <repo>`: the spec tools of a project since KIT-081 stage 1, which run from the kit: `remove` deletes the `.github/spec-lint/` copy an older sync generated, only when its `README.md` carries the generated heading and only the kit-named files (validators, schemas, `KIT_VERSION`, that README, the validators' byte caches), keeping any other file with a `sync: kept` line and never touching a symbolic link, then warns about each workflow line that still names the copy; `check` fails on a generated copy left, on such a workflow line (`file:line` and the fix) and, with `--spec`, on no workflow that runs the spec tools (the spec-tools action, or `check_spec.py` from `$AI_KIT_DIR`; `--workflow` names the one that must); `workflow` writes `spec-lint.yml` (or the `--workflow` name) from the template with the action pinned to `git rev-parse HEAD` and `# v<VERSION>` when none runs them and the file is missing, and warns when that commit is not the release tag | called by `sync-project.sh` |
| `sync_agents_md.py` | `preflight|write|check <repo> <kit-version> <rules-dir>`: the path-rule block in each folder's `AGENTS.md`, built from the rules `sync-project.sh` rendered: one block per folder a rule's globs start in, for runtimes that load no rule by path; `write` replaces, appends, creates or removes it, `check` exits 1 on a missing, diverging or stale block, `preflight` refuses a symbolic link, a folder reached through a symbolic link or broken markers before any write; the text around the block and its dominant line ending are kept, and nested checkouts keep their own blocks (KIT-067) | called by `sync-project.sh` |
| `sync_just.py` | `write|check <repo> <profile-list>`: no project justfile (KIT-085; skill `sdd-implement` runs the kit's module with `-f` and `-d`), so it writes none and requires no import; `write` removes the starter `justfile` older syncs wrote (its whole text is a sync's comment lines and one kit import line), each `kit.just` or `kit-<profile>.just` marked as generated (KIT-081 stage 1b) and rewrites a line importing the removed `kit.just` in a single-profile folder's justfile; a justfile with any other content stays whole (`sync: kept` when it imports a kit module), as does an unmarked file, and nothing is read or removed through a symbolic link; `check` exits 1 on a starter or marked copy left and on a line importing the removed `kit.just` (`file:line` and the fix) | called by `sync-project.sh` |
| `profile.py` | `resolve [--section S] [--json] [--file F] [ROOT]`: the project profile, `.ai-kit.yaml` at the git top level, validated by `platforms/ci/schemas/profile.schema.json` (every key with a default and one `x-read-by` phase, unknown keys refused, `x-<name>` keys ignored); a key the project sets nowhere takes its `project.kind` preset, else its default (KIT-088); the file is the only home since KIT-087 P4 (no legacy home, no alias, no `migrate`); a missing file is every default plus one warning; `--file` and `spec_root` must stay under the root; standard library, Python 3.9, the YAML parser and checks of `check_spec.py`, which `--params` delegates to it (its notes as one stderr line); exit 1 on an invalid profile, 2 on a usage error | called by the kit's skills, hooks, `sync-project.sh` and the spec-tools action, never by a project |
