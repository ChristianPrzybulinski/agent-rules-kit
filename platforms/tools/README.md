# tools/ — kit lifecycle on the machine

| File | Scope | When to use |
|---|---|---|
| `bootstrap.sh` | clones the kit, connects agent plugins, installs launchd, then runs doctor | first setup on a machine |
| `refresh.sh` | fast-forwards main and updates Codex/Claude marketplaces and plugins; when the pull changed `refresh.sh` or `codex-bin.sh` it hands over once to the pulled script (KIT-046); reinstalls a Claude plugin whose cache differs from the kit (KIT-013); logs a `skip:` line when the `claude` or `codex` CLI is missing (KIT-022) | scheduled refresh or manual update |
| `doctor.sh` | verifies plugins/symlinks, warns on a stale Claude plugin cache, merges Devin import policy, cleans legacy state and checks budgets; `AI_KIT_USER_RULES=1` restores user-level rule symlinks (default 0: repos carry `.claude/rules`) | diagnose setup or after refresh |
| `codex-bin.sh` | finds the Codex CLI for bootstrap, refresh and doctor, which source it: `$CODEX_BIN`, `codex` on `PATH`, ChatGPT.app or Codex.app, `~/.cache/codex-runtimes`; run directly it prints the CLI it found (KIT-023) | check which Codex CLI the kit uses |
| `smoke.sh` | runs bootstrap and doctor against isolated throwaway homes | after lifecycle changes; in CI |
| `vendor.sh` | installs pinned third-party skills; `--check` verifies the lock | update or verify vendored skills |
| `complexity.py` | advisory complexity of changed functions: Java CRAP from a JaCoCo XML the build wrote, GDScript CC from `gdradon cc` joined by function name, or CRAP when `--gd-coverage JSON` (a `gd_coverage.py --json` report, repeatable) holds the function, joined by repository-relative path and `func` line; `[FILE...]` measures whole files; exit 0, `--threshold N` exits 1 at N and 2 on a missing or unreadable report or gdradon (KIT-031, KIT-034) | before a PR or a completion verdict that touches `.java` or `.gd` |
| `gd_duplicates.py` | advisory structural duplicates of changed GDScript functions: gdtoolkit parse tree, names and numbers normalised, strings kept, Jaccard of subtree fingerprints, pairs at 0.82 or more against the whole tree; `[FILE...]` or `--all` widen it; fingerprints cached by file content under `$XDG_CACHE_HOME/ai-kit/gd-duplicates`; exit 0, `--threshold S` exits 1 at S and 2 without gdtoolkit (KIT-033) | before a PR that touches `.gd` |
| `gd_coverage.py` | advisory line and branch coverage of GDScript functions under gdUnit4: `git archive` of the Godot project into a temporary folder (LFS pointers filled from the local store), probes inserted with gdtoolkit without changing a line number, one headless import and the gdUnit4 suite under `nice -n 10` with `HOME` in the folder, killed with its child processes after `--timeout S` (default 1800); `--exclude PATH` leaves a script a test copies out of the project without probes; `--ignore SUITE`, repeatable, goes to gdUnit4 as `-i` (a suite name, a path or `suite:test`) to leave out tests that inspect the project's own autoloads or dependencies and so see the probes; `HOME` moves, so a test that starts `python3` and imports user site-packages needs the caller's `PYTHONUSERBASE`; one `path:line function lines C/T branches C/T` line per function, `--json FILE` per statement and outcome; `[FILE...]` or `--base REF` narrow it; exit 0, and 2 when the run does not count (timeout, exit other than 0 or 101, no test case, no counters) or godot, gdUnit4 or gdtoolkit is missing (KIT-034) | before a PR that touches `.gd` game rules |
| `gd_mutation.py` | advisory mutation testing of GDScript functions under gdUnit4 with PIT 1.30.0's default operators (boundary, negated conditions, math, increments, negation, void calls and typed returns), placed from the gdtoolkit tree as one edit that keeps every line number and parses again, never a value the return type cannot hold; `git archive` copy imported once, one APFS clone per worker (`--workers N`, an upper bound: every Godot run starts only while fewer than 2 gate runs of the review loop hold the host, and one beside another of ours only while the load is below the core count), the suites under `--tests` that name the file's `class_name` or `res://` path, an unmutated baseline per selection and a timeout of 10 × its time plus `--timeout-constant S` (default 30, PIT's shape); statuses killed, survived, timed out, invalid, error, "not run" when writing or running a mutant raises, "no tests" and, with `--coverage` (`gd_coverage.py --json`), "no coverage" without a run; one survivor per line, `--json FILE` per mutant; `--cache FILE` (default `$XDG_CACHE_HOME/ai-kit/gd-mutation/cache.json`) keeps killed, survived and invalid (a timed-out mutant runs again) under a hash of the function's text and its selected test files, so a second run with nothing changed starts no Godot, and `--no-cache` runs every mutant; `[FILE...]` or `--base REF` narrow it; exit 0, and 2 when godot, gdUnit4 or gdtoolkit is missing, the import or a baseline fails or a mutant is not run (KIT-035) | before a PR that touches `.gd` game rules |
| `kpi.py` | per-batch review-loop KPIs from a `ledger.csv` | after each loop batch; before and after a kit rule change |
| `bump_version.py` | `X.Y.Z [--date YYYY-MM-DD]` writes `VERSION`, every manifest `"version"` and the CHANGELOG heading; refuses a version not above `VERSION`, a dirty tree or an empty `[Unreleased]`; `--notes X.Y.Z` prints the release notes as `release.yml` cuts them (KIT-019) | first step of a kit release (`CONTRIBUTING.md` § Versioning) |
| `check.sh` | validates the kit and Claude manifests; `--spec <dir>` validates project specs | after any kit change; in CI |
| `gen_index.py` | generates every `plugins/*/INDEX.md` from the plugin's `skills/*/SKILL.md` frontmatter and its `AGENTS.md`, `rules/`, `agents/`, `templates/`, `evals/` and `hooks/`; `--check` lists stale files and exits 1 (KIT-040) | after adding, removing or renaming a plugin entry or changing a skill `description`; `check.sh` runs the check |
| `sync-project.sh` | copies spec validation files into a project that has `docs/spec` and generates `CLAUDE.md` (imports `AGENTS.md`), `.claude/settings.json` (kit marketplace and `guardrails@ai-kit`; profile `godot|java|docs|python`: `--profile`, else the list `.claude/skills/KIT_MANIFEST.json` records, else inferred, and the run prints which source won; a comma list such as `docs,godot:client,java:server` syncs the union for a monorepo, `:<dir>` scoping that profile's rule globs) and `.claude/rules/guardrails-<rule>.md` (the profile's path rules per `sync-profiles.txt`, marked generated); `--check` compares all of them and scans the repo's `*.md` for obsolete kit paths; `--workflow <file>` names the CI file that runs `check_spec.py` (any name is accepted if it does); `--vendor-skills` copies the profile's skills into `.claude/skills/` with a hashed `KIT_MANIFEST.json` | initialize or refresh a project; in the project's CI |
| `sync-profiles.txt` | one line per `guardrails` skill and rule: the profiles (`godot java python docs`, or `-` for none) that receive its vendored copy or its `.claude/rules/` file; `sync-project.sh` reads it and `check_kit.py` requires exactly one line for each (KIT-047) | after adding, removing or renaming a `guardrails` skill or rule |
