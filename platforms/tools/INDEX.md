# tools/ — kit lifecycle on the machine

| File | Scope | When to use |
|---|---|---|
| `bootstrap.sh` | clones the kit, connects agent plugins, installs launchd, then runs doctor | first setup on a machine |
| `refresh.sh` | fast-forwards main and updates Codex/Claude marketplaces and plugins; reinstalls a Claude plugin whose cache differs from the kit (KIT-013); logs a `skip:` line when the `claude` or `codex` CLI is missing (KIT-022) | scheduled refresh or manual update |
| `doctor.sh` | verifies plugins/symlinks, warns on a stale Claude plugin cache, merges Devin import policy, cleans legacy state and checks budgets; `AI_KIT_USER_RULES=1` restores user-level rule symlinks (default 0: repos carry `.claude/rules`) | diagnose setup or after refresh |
| `codex-bin.sh` | finds the Codex CLI for bootstrap, refresh and doctor, which source it: `$CODEX_BIN`, `codex` on `PATH`, ChatGPT.app or Codex.app, `~/.cache/codex-runtimes`; run directly it prints the CLI it found (KIT-023) | check which Codex CLI the kit uses |
| `smoke.sh` | runs bootstrap and doctor against isolated throwaway homes | after lifecycle changes; in CI |
| `vendor.sh` | installs pinned third-party skills; `--check` verifies the lock | update or verify vendored skills |
| `complexity.py` | advisory complexity of changed functions: Java CRAP from a JaCoCo XML the build wrote, GDScript CC from `gdradon cc` joined by function name; `[FILE...]` measures whole files; exit 0, `--threshold N` exits 1 at N and 2 on a missing report or gdradon (KIT-031) | before a PR or a completion verdict that touches `.java` or `.gd` |
| `kpi.py` | per-batch review-loop KPIs from a `ledger.csv` | after each loop batch; before and after a kit rule change |
| `bump_version.py` | `X.Y.Z [--date YYYY-MM-DD]` writes `VERSION`, every manifest `"version"` and the CHANGELOG heading; refuses a version not above `VERSION`, a dirty tree or an empty `[Unreleased]`; `--notes X.Y.Z` prints the release notes as `release.yml` cuts them (KIT-019) | first step of a kit release (`docs/maintenance.md` § Versioning) |
| `check.sh` | validates the kit and Claude manifests; `--spec <dir>` validates project specs | after any kit change; in CI |
| `sync-project.sh` | copies spec validation files into a project that has `docs/spec` and generates `CLAUDE.md` (imports `AGENTS.md`), `.claude/settings.json` (kit marketplace, `enabledPlugins` per profile `godot|java|docs`: `--profile`, else the list `.claude/skills/KIT_MANIFEST.json` records, else inferred, and the run prints which source won; a comma list such as `docs,godot:client,java:server` syncs the union for a monorepo, `:<dir>` scoping that profile's rule globs) and `.claude/rules/<plugin>-<rule>.md` (the profile's path rules, marked generated); `--check` compares all of them and scans the repo's `*.md` for obsolete kit paths; `--workflow <file>` names the CI file that runs `check_spec.py` (any name is accepted if it does); `--vendor-skills` copies the profile's skills into `.claude/skills/` with a hashed `KIT_MANIFEST.json` | initialize or refresh a project; in the project's CI |
