# kit github

CI, PR and label governance templates for GitHub Actions.

## How to use

| File | Destination in the project |
|---|---|
| `workflows/*.yml` | `.github/workflows/` |
| `PULL_REQUEST_TEMPLATE.md` | `.github/PULL_REQUEST_TEMPLATE.md` |
| `REVIEW.md` | `REVIEW.md` at the repository root (read by hosted Claude Code Review; also the checklist for any reviewer) |
| `ISSUE_TEMPLATE/task.md` | `.github/ISSUE_TEMPLATE/task.md` (one issue per task row, filled verbatim by `sdd-to-card`) |
| `CODEOWNERS` | `.github/CODEOWNERS` (edit the user) |
| `dependabot.yml` | `.github/dependabot.yml` |
| `labels.json` | reference for `scripts/labels-sync.sh` |
| `scripts/labels-sync.sh` | run from anywhere inside the repo: `bash platforms/kits/github/scripts/labels-sync.sh` |

`ci-java.yml` and `ci-godot.yml` are **reusable** workflows (`on: workflow_call`): copy them to the project's `.github/workflows/` and call them from a thin project workflow:

```yaml
# .github/workflows/ci.yml
name: ci
on:
  pull_request:
  workflow_dispatch:
jobs:
  java:
    uses: ./.github/workflows/ci-java.yml
    secrets:
      NVD_API_KEY: ${{ secrets.NVD_API_KEY }}
  godot:
    uses: ./.github/workflows/ci-godot.yml
    # with:
    #   godot-version: '4.7.2'
    #   test-runner: 'gdunit4'   # or 'gut'
```

## Notes

- `ci-java.yml` assumes the Maven wrapper (`./mvnw`), JDK 25 Temurin and the `platforms/kits/java-maven/pom-parent.xml` gates (Spotless, JaCoCo, PITest). Its `changes` job skips build/tests on docs-only diffs and runs `dependency-check` only when build files change; the mojo is pinned (`dependency-check-maven:13.0.0`, supports `nvdApiKeyEnvironmentVariable`), `NVD_API_KEY` is a required secret, and the NVD data cache is saved even when the gate fails.
- `ci-godot.yml` runs in `barichello/godot-ci:<godot-version>`. The import step runs `--import` (not `--quit`, which skips the import scan) and a boot-proof step greps the `--quit` log for `SCRIPT ERROR|Parser Error`, because that exit code is 0 after a script error. The `test-runner` input selects gdUnit4 (`addons/gdUnit4`, default) or GUT (`addons/gut`); a missing runner addon or zero test suites fails the build — tests are never silently skipped — and `reports/` plus the runner log upload as the `godot-test-reports` artifact. Its `changes` job exposes `code`/`export` outputs so the caller can gate a manual export job (requires `export_presets.cfg` committed to the repo). LFS objects restore from a cache keyed on the LFS file list. The `lint` job needs `requirements-gdtoolkit.txt` and `.gdlintrc` at the project root (from `platforms/kits/godot/`).
- `spec-lint.yml` validates `docs/spec/**` **without checking out the kit**: it uses the local copy in `.github/spec-lint/` (generated by `platforms/tools/sync-project.sh`; no token, no other repo).
- `pr-contract.yml` is a **reusable** workflow running the no-model PR gates (`platforms/ci/validations/pr_gates.py`). It checks out the gates repository at a protected ref (`gates-ref`, never the PR head — the job holds the secret) and needs a `GATES_TOKEN` able to read the backlog repo's issues; `repo`, `gates-repo`, `script` and `config` are inputs, and `proof-commands` is the output the caller's `proof` job runs.
- `gitleaks.yml` needs `fetch-depth: 0` to scan the whole PR diff.
- `ISSUE_TEMPLATE/task.md` is the body contract `sdd-to-card` fills; the `Directive` tiers map to vendor models in the project, never in the kit.
- `REVIEW.md` holds the five review criteria of `plugins/quality-core/templates/doc-review-checklist.md` without project-specific gates; a project adds its own gates (coverage, mutation score, contract version field) under the matching heading. Hosted Claude Code Review (Team/Enterprise) reads it from the repository root; the local `/code-review` command does not (it reads `CLAUDE.md`); both facts checked against code.claude.com/docs/en/code-review on 2026-10-06.
