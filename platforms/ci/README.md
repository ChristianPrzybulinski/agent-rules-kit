# platforms/ci/ — schemas and validations

`schemas/`: JSON Schema (draft 2020-12) for kit frontmatter and project `docs/spec/` artifacts. `validations/`: scripts run by `platforms/tools/check.sh` and by kit and project CI, and the kit's tests, which `platforms/tools/run_tests.py` selects by layer (KIT-077). `fixtures/consumer/`: a small consumer project (a spec at the root, Python code and tests under `tools/`) that the functional layer, `validations/test_consumer_fixture.py` in `.github/workflows/ci-full.yml`, copies, syncs the kit into and checks with its own spec lint, `just verify` and `sync-project.sh --check`.

| Schema | Validates | Target file-name rule |
|---|---|---|
| `agent.schema.json` | shared Devin/Claude profiles under `plugins/*/agents/` | lowercase and Claude tool lists map 1:1 |
| `knowledge.schema.json` | legacy knowledge-note frontmatter retained for compatibility | `verified` (date) + `sources` (URLs) required |
| `rule.schema.json` | `plugins/*/rules/*.md` | `trigger` is `glob`, `model_decision`, or `manual` |
| `skill.schema.json` | `plugins/*/skills/<name>/SKILL.md` (non-vendor) | `name` = folder; `triggers`; allowed tools |
| `skills-lock.schema.json` | lines of `platforms/kits/third-party/skills.lock` | 40-hex `sha` |
| `spec.schema.json` | a project's `docs/spec/spec.md` | fixed; optional `decision_kinds` (kind → decision id prefix) and `sdd` (the project's process parameters with their defaults, KIT-067) |
| `feature.schema.json` | `docs/spec/features/*.md` | `FEAT-nnn-slug.md` |
| `requirement.schema.json` | `docs/spec/requirements/{functional,non-functional}/*.md` | `REQ-F-nnn-*` / `REQ-NF-nnn-*`; optional `status` (`proposed`, `approved`, `retired`) |
| `decision.schema.json` | `docs/spec/decisions/*.md` | `DEC-nnn-slug.md`, or `<PREFIX>-nnn-slug.md` with the `kind` whose prefix `spec.md` `decision_kinds` declares |
| `debt.schema.json` | `docs/spec/debts/*.md` | `DEBT-nnn-slug.md` |
| `need.schema.json` | `docs/spec/needs/*.md` | `NEED-nnn-slug.md`; `type` and `status` enums, forward links only |
| `journey.schema.json` | `docs/spec/journeys/*.md` | `J-NN[-slug].md` |
| `task.schema.json` | `docs/spec/tasks/*.md`, one cut item per file when `sdd.tracker` is `none` (KIT-068) | `TASK-nnn-slug.md`; `feat`, `rows`, `status` (`todo`, `doing`, `blocked`, `done`, `cancelled`) |
| `progress.schema.json` | `docs/spec/progress/FEAT-nnn.json`, kept for FEATs cut before KIT-068 | `FEAT-nnn.json`, equal to its `feat` |

The nine spec schemas (`spec`, `feature`, `requirement`, `decision`, `debt`, `need`, `task`, `journey`, `progress`) go to projects **as a copy**: `platforms/tools/sync-project.sh` installs `check_spec.py`, `row_checks.py`, `pr_gates.py`, `spec_trace.py` and the schemas into the project's `.github/spec-lint/`, and `platforms/kits/github/workflows/spec-lint.yml` runs them locally without a kit checkout or token. `journey.schema.json` is installed only when the project has `docs/spec/journeys/`; `spec_trace.py` goes to every project since KIT-073. `check_docs_structure.py` is installed only while `sdd.doc_structure.enabled` is true, and removed when it turns false (KIT-074).

| Validation | Scope |
|---|---|
| `validations/check_kit.py` | multi-plugin layout, manifests and dependency graph, frontmatters, description budget, README completeness and `INDEX.md` placement (self-test `validations/test_check_kit_readmes.py`), links, vendor lock, duplication (`--links` includes `~/.ai-kit/...`) |
| `validations/check_spec.py` | a project's `docs/spec`: schema + id=prefix + FEAT↔REQ cross-check (ids exist, both frontmatters list each link; a REQ with no FEAT must be listed by an open NEED) + NEED forward links (each listed id exists with its kind; `refined`/`delivered` backed by links, `delivered` only with delivered FEATs or, for a `decision` NEED with no FEAT, an approved decision) + unique IDs + `progress/*.json` (schema, feat exists, name = feat, unique task ids) + the `spec.md` `sdd` block checked against `spec.schema.json` with or without pyyaml; `--params <spec-dir> <schemas-dir>` prints that block resolved, every absent key at its default (KIT-067) + `tasks/TASK-nnn` files and the FEAT rows' `Item` cells naming each other, an open FEAT's longest own `Depends on` chain within `sdd.max_chain`, no cycle and no own id that is not a row, a WARN above `sdd.max_feat_tasks` rows or a 1000-character Task cell + `baseline.json` (KIT-068): every failure carries a rule id, old findings held per rule and artifact (a count, or for `task-chain` the held chain length) print as `BASELINE` and do not block, the file only shrinks (`--baseline-init` once, `--baseline-update` lowers, `--baseline-against <older.json>` fails an added or raised entry and skips a missing file; the `spec-lint.yml` template runs it on every pull request) + a validated or delivered FEAT carries the History line `spec_trace.py validate`/`deliver` writes, or `delivered before sdd-review` (KIT-069); self-tests `validations/test_check_spec.py`, `validations/test_check_spec_tasks.py`, `validations/test_check_spec_closure.py` |
| `validations/spec_trace.py` | a project's `docs/spec`: journey step-table link checks, FEAT↔REQ symmetry, `traceability.md` generation/staleness (required when `sdd.journeys` is on, absent = when `docs/spec/journeys/` exists, or once the file exists), `impact`/`mark-done`/`status` (rows derive `in-progress` at most), `validate`/`deliver` (the only writers of FEAT `validated`/`delivered`, KIT-069), `lint` (sdd-review's stale-text, History-split and trace lint), `checklist J-NN …` (the owner's step checklist of approved journeys), the `spec.md` index check with `sdd.spec_index`, `sync-status [--write]` (`sdd.tracker: github`: row Status from the task issues and their closing PRs through `gh api`, per `task-issue.md` § States, a `cancelled` row never reopened; never `validated`/`delivered`; `--write` refreshes the `spec.md` blocks between `sync-status` and `sync-counts` markers); the spec folder argument defaults to `docs/spec` (KIT-073); self-tests `validations/test_spec_trace.py`, `validations/test_spec_trace_closure.py`, `validations/test_spec_trace_lint.py`, `validations/test_spec_trace_checklist.py`, `validations/test_spec_trace_sync_status.py` |
| `validations/row_checks.py` | a project's task rows before the cut: rules a–k of `sdd-tasks/references/row-checks.md`, driven by the `sdd:` block (`components`, `row_checks`, `visual_approval`) and the PR-gates config, exit 2 on a config it cannot use or any crash; the default `sdd.row_check` (KIT-073); self-tests `validations/test_row_checks.py`, `validations/test_row_checks_contract.py` |
| `validations/check_docs_structure.py` | opt-in (`sdd.doc_structure.enabled` in a project's `docs/spec/spec.md`, KIT-074): every authored folder in `git ls-files` has a `README.md` with a `# ` title and the configured `headings`, every `done/` folder an `INDEX.md` naming each direct child (`done_index`), except the globs of the `exempt` file, `.github` itself and the folders `sync-project.sh` generates; reads the block through `check_spec.py --params` beside it; `sync-project.sh` vendors it into `.github/spec-lint/` when enabled; self-test `validations/test_check_docs_structure.py` |
| `validations/pr_gates.py` | the no-model PR gates against the GitHub REST API, driven by a project JSON config; served by `platforms/kits/github/workflows/pr-contract.yml`; its `command_allowed` (allowlist, `! git diff` only with `--quiet`/`--exit-code`, and with a component folder the KIT-080 hygiene rules: no `..`, no expansion outside a leading anchor, no inline code) is the one `row_checks.py` imports; self-test `validations/test_pr_gates_command.py` |

Without `pyyaml`/`jsonschema`: structural validation with a WARN; with `CI=1`, their absence is an error.
