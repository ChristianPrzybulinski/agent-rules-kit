# platforms/ci/ — schemas and validations

`schemas/`: JSON Schema (draft 2020-12) for kit frontmatter and project `docs/spec/` artifacts. `actions/spec-tools/`: the composite action a project's CI pins by commit SHA to run the spec validators and schemas of that kit commit (KIT-081 stage 1; inputs in its README). `actions/gitleaks/`: the composite action a project's CI pins the same way to run the kit's secret scan as a step, the gitleaks CLI at the pin of the kit's own scan (KIT-084; input in its README). `validations/`: scripts run by `platforms/tools/check.sh` and by kit and project CI, and the kit's tests, which `platforms/tools/run_tests.py` selects by layer (KIT-077). `fixtures/consumer/`: a small consumer project (a spec at the root, Python code and tests under `tools/`) that the functional layer, `validations/test_consumer_fixture.py` in `.github/workflows/ci-full.yml`, copies, syncs the kit into and checks with its own spec lint, `just verify` and `sync-project.sh --check`.

The eleven spec schemas (`spec`, `feature`, `requirement`, `decision`, `debt`, `need`, `task`, `journey`, `process`, `enabler`, `progress`) and the spec validators stay in the kit; a project carries no copy of them (KIT-081 stage 1). A session runs them from the installed kit (`${AI_KIT_DIR:-$HOME/.ai-kit}/platforms/ci/validations/`, with `platforms/ci/schemas/`): the skills, the post-edit hook and the `docs.just` `lint` recipe. A project's CI runs them through `actions/spec-tools/action.yml`, pinned to a kit commit by SHA with the release in a comment, which `platforms/kits/github/workflows/spec-lint.yml` and `pr-contract.yml` call; Dependabot or Renovate bumps the pin when the kit releases (`platforms/kits/github/README.md`). Until stage 1, `platforms/tools/sync-project.sh` copied them into the project's `.github/spec-lint/`; it now removes that copy.
