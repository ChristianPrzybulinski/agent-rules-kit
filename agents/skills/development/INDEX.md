# skills/development/ — development by stack

| Skill | Scope | When to use |
|---|---|---|
| `java-standards` | modern Java, Clean Code/Architecture, tests | `*.java`, `pom.xml` |
| `godot-standards` | Godot 2D, GDScript, nodes, signals, autoloads | `*.gd`, `*.tscn` |
| `asset-import` | sprites/tilesets/maps → Godot, non-destructive, with manifest | import art from the archive or external sources |
| `protocol-contract` | client↔server contract messages with versioning | new field/message; client and server disagree |
| `investigate` | root cause of a bug/regression/slowness, with reproduction before the fix | "doesn't work", incident |
| `clean-code` | names, functions, classes, comments, tests | write/review production code |
| `simplicity` | simplicity ladder (YAGNI), deliberate simplification | design a solution, oversized PR, dependency choice |
| `testing` | domain coverage gates, happy+sad integration, what not to test | create/change tests, build gates |
| `twelve-factor` | env config, stateless processes, dev/prod parity | configure app, Docker, env vars, deploy |
| `clean-architecture` | layers, dependency rule, ports/adapters, DTOs | create a module/layer, decide where a class lives |
| `ddd-and-patterns` | tactical DDD, pattern catalog (when yes / when no) | model a domain, choose a pattern |
