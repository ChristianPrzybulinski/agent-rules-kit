# DBeaver

A **human** inspection tool. The agent does not operate the GUI; it guides and prepares files. The schema source of truth is Flyway — changes made in DBeaver do **not** count until they become `V<n>__*.sql`.

## connect

1. Read the project's `.env` (do not print the password): host `127.0.0.1`, port, db, user.
2. DBeaver → New connection → PostgreSQL → fill in; "Show all databases" off; save the password in the macOS keychain (DBeaver option), not in an exported file.
3. DBeaver's connection file (`~/Library/DBeaverData/workspace6/General/.dbeaver/data-sources.json`) does **not** go into the repo.

## export (test data)

- Prefer a versioned SQL script in `src/test/resources/fixtures/*.sql` generated by `pg_dump --data-only --table=<t>` over a GUI export (reproducible).
- Real personal data → never in a fixture. Anonymize first.

## er-diagram

- DBeaver → schema → ER Diagram → export PNG/SVG to `docs/architecture/er-<date>.svg`.
- The diagram is derived: regenerate after a relevant migration; note the migration version (`V<n>`) in the caption.

## Do not

- Change the schema via the GUI in any non-disposable environment.
- Run `DELETE`/`UPDATE` without `WHERE` — DBeaver asks for confirmation; still, ask first.
