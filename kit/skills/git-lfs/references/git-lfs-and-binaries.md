# Binaries and Git LFS

## Rules

- Root `.gitattributes` defines LFS **before** the first binary enters. Adding a pattern later requires `git lfs migrate` (rewrites history).
- Goes to LFS: `*.png *.jpg *.webp *.wav *.ogg *.mp3 *.ttf *.otf *.psd *.kra *.aseprite *.zip` and any file >1 MB.
- **Never enters the repo**: raw/legacy archive (stays outside, with a recorded hash), build exports (`build/`, `*.exe`, `*.app`, `*.pck`), `.godot/`, `target/`, database dumps.
- File generated by a deterministic script (atlas, tileset, conversion) → do **not** version it; version the script + manifest (origin, hash, parameters). Exception: if generating takes >5 min or requires a tool missing in CI — then version it in LFS with the manifest.
- Godot: version `*.import`; never `.godot/`.

## Legacy preservation

- Originals are read-only, outside the repo, with a versioned `SHA256SUMS`.
- Every conversion writes to a separate area with `manifest.json` (origin, input hash, output hash, tool+version, parameters).
- Never overwrite an original; never "clean" the archive automatically.

## Condition → action

- New binary file type → add it to `.gitattributes` **in the same commit** as the first file.
- `git status` shows a >1 MB binary without LFS → stop; fix before committing.
- Fresh clone → `git lfs install && git lfs pull`.
- GitHub LFS quota (Free/Pro: 10 GiB storage + 10 GiB bandwidth/month — see `lfs-quotas-github.md`) → monitor with `gh api repos/{owner}/{repo}` + `git lfs ls-files -s`; large archives stay off GitHub.
